::: info 這篇的脈絡
叮咚記帳是我的 side project：一個讀付款通知自動記帳的 Android App，後面有一個 Go 後端，還有一個掛在這個部落格上的官網與管理後台。
三個程式倉庫、三種語言，我一個人做。這篇不是在講「AI 幫我寫了多少行」，而是在講：**當同時有好幾個 AI 在改同一個產品，怎麼讓它們不互相踩腳。**
:::

## 分工：一個資料夾一個小精靈

工作區長這樣：

```text
DinDon/                  ← 協作用的倉庫：溝通板、待辦、營運設定，不放程式
├── DinDon_Android/      ← 前端 Claude（Kotlin、Compose）
├── DinDon_BackEnd/      ← 後端 Claude（Go、Cloud Run、Neon）
├── DinDon_Web/          ← 網頁 Claude（這個部落格，用捷徑掛進來）
└── coordination/        ← 溝通板
```

VS Code 永遠開最外層那個資料夾，一個小精靈就是一個對話分頁。開新對話的第一句話講清楚角色：「你是前端 Claude，負責 `DinDon_Android/`，其他資料夾只讀」。

另外還有兩個特殊角色：

- **上架小精靈**：是一個子代理（subagent），只陪我填 Play Console、回答上架政策問題。它**只讀程式、不改程式**，要改 App 就開單給前端。
- **目錄小精靈**：管工作區本身的結構與規則，也不改程式。

## 溝通板：它們看不到彼此，所以要一塊公告欄

每個對話是獨立的，前端 Claude 不知道後端 Claude 剛改了什麼。一開始我用一份大文件讓大家輪流往下寫，長到 120KB，每次「先讀溝通板」就吃掉一大塊上下文，三個 AI 還會同時寫同一份檔案互相蓋掉。

後來改成這樣：

```text
coordination/
├── board.md        ← 只列「還沒結案」的單，一行一張。開工只讀這份
├── threads/        ← 一件事一個檔案：0053-feedback-batch-review.md
└── archive/        ← 結案的單
```

規則只有幾條，但每一條都是被咬過才加的：

1. **只放通知、請求、問題，不放介面定義。** API 格式只有一份，在後端倉庫的 `api.md`，只有後端改。溝通板最多寫「api.md 第 8 節改了」。抄過來就會有兩份，遲早對不上。
2. **一件事一個檔案，別人的單只能加回覆、改狀態。**
3. **開單的人結案。**
4. **破壞性操作先開單。** 清資料庫、改 migration、換網址，確認對方沒在用再動手。

一張典型的單：後端加了「批次審核回報」的 API，開單給網頁：「使用者被垃圾回報淹沒了，後台要能一次處理」。網頁 Claude 開工先讀溝通板，看到單，讀 `api.md`，做完回覆、改狀態；後端看到回覆再結案。

## 每個倉庫有自己的規則書

每個倉庫根目錄一份 `CLAUDE.md`：用什麼版本、怎麼建置、目錄怎麼分、哪些事絕對不能做。更細的做法寫成 skill（例如「這個後端的 handler 怎麼寫、錯誤該回幾號」），AI 碰到對應的事才載入。

一開始後端裝了 46 個現成的 Go skill，後來評估只留十幾個，並補上四個「這個專案實際怎麼做」的。**通用教材跟專案慣例衝突時，專案慣例贏**，而且要寫出理由，不然下一個對話又會被通用教材帶走。

另外每個角色都寫開發記錄：我問了什麼、它做了什麼、驗證了什麼、留下什麼沒做。下一個對話打開就知道來龍去脈。

## 踩過的坑

- **「編譯過」不等於「能用」。** 有一次主題設定不同步，建置全綠，實機一開就錯。之後的規矩是 UI 改動一定要在模擬器實際點過；網頁則是用無頭瀏覽器實際操作、截圖看過才算數。
- **本機全綠，CI 卻紅。** 我的工作樹有一行還沒提交的文案，AI 全倉庫自動修 lint 時修到了我的副本，但刻意沒把我的檔案收進 commit，結果線上版本還留著錯。它自己抓 CI log 才找到原因。
- **太早去看新檔案，被快取咬。** 分享預覽圖剛推上去、還沒部署完，就去抓了一次圖片網址，前面的 Cloudflare 把那次 404 快取了 4 小時。最後只能換檔名繞過去。
- **看起來能跑的元件其實沒被解析。** 部落格的 markdown 頁面裡寫的元件，從來沒被自動註冊外掛吃到，一直是瀏覽器不認得的標籤。建置不會報錯，是實際打開頁面、檢查 DOM 才發現。

這幾個坑的共通點：**AI 很會把事情做完，但「做完」的定義要由你給。** 我給的定義越具體（在模擬器點過、CI 綠了、線上抓得到），它交出來的東西就越可靠。

## 我還是那個做決定的人

AI 不會自己決定要不要上線、要不要刪資料、要不要改對外承諾的數字。這些事它會停下來問，或開單。這條線畫清楚之後，放手讓它做反而比較安心。
