## 懶人包
- 遞迴版好寫好讀，但每走一層都多一個函式呼叫，樹很深的時候會撞到呼叫堆疊上限。
- 迭代版把「待處理的節點」放進自己的陣列 `temp`，用 `pop()` 逐次把 `left`、`right` 拆出來，直到找到目標為止。
- `temp` 裡放的是原本 `tree` 節點的 reference，從頭到尾沒有複製資料，記憶體一直是同一份。
- 也因為是 reference，`console.log` 印物件時會顯示「展開當下」的狀態，看不到被取出的過程，除錯時要印快照。

## 技術拆解

### 二元樹長什麼樣子
二元樹就是每個節點最多有兩個小孩：`left` 和 `right`。在前端它通常長這樣：

```ts
interface TreeNode {
    value: number;
    left: TreeNode | null;
    right: TreeNode | null;
}

const tree: TreeNode = {
    value: 1,
    left: {
        value: 2,
        left: { value: 4, left: null, right: null },
        right: { value: 5, left: null, right: null }
    },
    right: {
        value: 3,
        left: null,
        right: { value: 6, left: null, right: null }
    }
};
```

需求很單純：給一個 `value`，把那個節點找出來。

### 遞迴：把問題丟給下一層
遞迴的想法像是問路：「你知道 6 在哪嗎？不知道的話，幫我問問你左邊和右邊的鄰居。」

```ts
function findRecursive(node: TreeNode | null, target: number): TreeNode | null {
    if (!node) { return null; }
    if (node.value === target) { return node; }

    return findRecursive(node.left, target) ?? findRecursive(node.right, target);
}
```

寫起來很漂亮，三行解決。代價是每往下一層，引擎就要在呼叫堆疊（call stack）上多疊一個執行環境，把參數、區域變數、要回到哪裡都記下來。樹平衡的時候深度大概是 log(n)，沒什麼感覺；但如果資料是一條歪斜的長鏈（例如巢狀很深的留言串），深度就等於節點數，幾萬層下去就是 `RangeError: Maximum call stack size exceeded`。

### 迭代：堆疊自己拿
迭代版的看點是：-|利用 `Array.pop()` 把包在 `temp` 陣列內的 `left` 和 `right` 逐次分割取出，直到找到目標為止|-。

```ts
function findIterative(tree: TreeNode, target: number): TreeNode | null {
    const temp: TreeNode[] = [tree];

    while (temp.length > 0) {
        const node = temp.pop()!;
        if (node.value === target) { return node; }

        // 先推 right 再推 left，pop 的時候才會先走左邊，順序跟遞迴版一樣
        if (node.right) { temp.push(node.right); }
        if (node.left) { temp.push(node.left); }
    }

    return null;
}
```

原本由引擎幫你管的呼叫堆疊，現在變成一個普通陣列。陣列放在 heap 上，能長到記憶體允許的大小，不會被呼叫堆疊的上限卡住。

### 為什麼說記憶體從頭到尾都是同一個
注意，因為 `temp` 是拿 `tree` 的原始資料包進陣列 `[tree]`，所以它裡面裝的是物件的 reference，不是複製出來的新物件。`node` 在迭代過程中只是引用 `tree` 中的某一個節點，`pop()` 拿出來、`push()` 放進去的，全都是同一批物件的地址。

這就是迭代在效能上比較優的原因：

1. 沒有複製資料，只是在搬地址。
2. 不需要為每一層建立新的函式執行環境。
3. 找到目標就直接 `return`，剩下的節點連碰都不碰。

### console.log 的陷阱
也因為是 reference，如果你在迴圈裡 `console.log(temp)`，到瀏覽器的 DevTools 展開來看，常常會發現每一次印出來的內容都一樣，看不到 `temp` 被取出的過程。

原因是 DevTools 印物件時先只記住 reference，等你點開那個小三角形才去讀內容，這時候迴圈早就跑完了，它只會反映出最後的狀態。要看每一步的樣子，就印快照：

```ts
console.log(temp.map(node => node.value)); // 印成純值陣列
console.log(structuredClone(temp)); // 或整包深拷貝一份
```

## 例子與對比

| | 遞迴 | 迭代（自己管 temp） |
| :--- | :--- | :--- |
| 可讀性 | 高，幾乎就是定義本身 | 中，要自己想 push 的順序 |
| 深度限制 | 受呼叫堆疊上限限制 | 只受記憶體限制 |
| 額外成本 | 每層一次函式呼叫 | 陣列的 push / pop |
| 改成廣度優先（BFS） | 不好改 | `pop()` 換成 `shift()` 就變佇列 |

最後一列是迭代版的隱藏福利：同一個骨架，`pop()` 從尾巴拿就是深度優先（DFS），`shift()` 從頭拿就是廣度優先（BFS）。想找「離根最近」的那個節點，換一個字就好：

```ts
function findNearest(tree: TreeNode, target: number): TreeNode | null {
    const queue: TreeNode[] = [tree];

    while (queue.length > 0) {
        const node = queue.shift()!;
        if (node.value === target) { return node; }

        if (node.left) { queue.push(node.left); }
        if (node.right) { queue.push(node.right); }
    }

    return null;
}
```

::: tip
`shift()` 每次都要把後面的元素往前挪，資料量很大的時候可以改用一個 index 指標往後走，不真的移除元素。
:::

想自己量看看的話，可以造一條很深的歪斜樹，兩個版本各跑一次：

```ts
function buildChain(depth: number): TreeNode {
    const root: TreeNode = { value: 0, left: null, right: null };
    let current = root;

    for (let i = 1; i < depth; i++) {
        current.left = { value: i, left: null, right: null };
        current = current.left;
    }

    return root;
}

const chain = buildChain(100000);
console.log(findIterative(chain, 99999)?.value); // 99999
console.log(findRecursive(chain, 99999)?.value); // RangeError: Maximum call stack size exceeded
```

## 結論
遞迴像請人幫你一層一層傳話，好溝通但人多了就塞車；迭代是自己拿著清單一間一間敲門，囉嗦一點，但不會被誰卡住。

平常的選單、分類樹用遞迴就好，讀起來最順；遇到深度不受你控制的資料，就把堆疊拿回自己手上。至於 `console.log` 印出來的東西對不上，先別懷疑人生，懷疑一下 reference。
