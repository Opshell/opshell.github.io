做行動版網頁時，網路上很多教學會推薦 `amfe-flexible` + `postcss-pxtorem` 這個組合（例如[這篇 Vue3 + Vite 的行動端適配](https://juejin.cn/post/7186236863714164793)）：設計稿寫多少 px 就寫多少 px，畫面會自動跟著螢幕寬度等比縮放，用起來很爽。
但專案如果要過無障礙檢測，這個組合就會出事。這篇講為什麼會壞、要怎麼改，寫給要做行動版、又要顧到無障礙的人。
:::

## 懶人包
- **不要用 `amfe-flexible`，會壞**：它把 `<html>` 的字級寫死成「螢幕寬度的十分之一」px，使用者在瀏覽器調大字級、或縮放頁面，文字都不會變大。
- 無障礙要求文字要能放大（WCAG 的「調整文字大小」要求能放大到 200% 而不失去內容或功能），這一條直接過不了。
- **只用 `postcss-pxtorem` 就可以了**：開發時照樣寫 px，建置時轉成 rem，根字級留給瀏覽器和使用者決定。
- 要跟著螢幕變化的是版面（寬度、間距），不是文字；版面用 `%`、`vw`、Flex／Grid 和 media query 處理。
- 順手檢查 viewport：不要寫 `user-scalable=no` 或 `maximum-scale=1`。

## 技術拆解

### 這兩個套件各做了什麼

| 套件 | 什麼時候作用 | 做了什麼 |
|---|---|---|
| `postcss-pxtorem` | 建置時 | 把 CSS 裡的 `px` 換算成 `rem` |
| `amfe-flexible` | 執行時（瀏覽器） | 用 JS 動態設定 `<html>` 的 `font-size` |

兩個搭在一起，就是「CSS 全部用 rem，而 1rem 等於螢幕寬度的十分之一」，畫面自然跟著螢幕寬度等比縮放。

### amfe-flexible 為什麼會壞

翻開 `amfe-flexible` 的原始碼，核心只有兩件事：

1. `<html>` 的 `font-size` 設成 `clientWidth / 10` px，視窗大小改變就重算。
2. `<body>` 的 `font-size` 設成 `12 * devicePixelRatio` px。

問題出在第一件。這就像一把尺的刻度跟著桌子寬度伸縮：桌子變窄，刻度就變小，量出來永遠是「十格」。

- **使用者調大瀏覽器預設字級**：沒用，因為 `<html>` 的字級被 inline style 寫死成 px，蓋掉了使用者的設定。
- **使用者把頁面放大到 200%**：CSS 像素下的 `clientWidth` 變成一半，`amfe-flexible` 跟著把 1rem 縮成一半，結果 rem 寫的文字在螢幕上**一樣大**。放大了個寂寞。

文字不能放大，對視力不好的使用者來說就是看不到。無障礙檢測會測這一條，於是就過不了審了。

第二件事也有副作用：沒有自己指定字級的文字，會繼承 `body` 的 `12 * dpr` px，在 3 倍螢幕的手機上就是 36px，常常要另外蓋掉。

### 只留 postcss-pxtorem

`postcss-pxtorem` 本身沒有問題，它只是建置時的換算工具。拿掉 `amfe-flexible` 之後：

- `<html>` 的字級回到瀏覽器預設（通常是 16px），使用者調大字級，rem 就跟著變大。
- 頁面放大到 200%，rem 寫的文字也跟著放大。
- 開發體驗不變，照樣照著設計稿寫 px。

唯一要調整的是 `rootValue`：設成 16，跟瀏覽器預設的根字級一致，換算出來的大小才會跟設計稿一樣。

### 那「等比縮放」怎麼辦

老實說，**文字本來就不該跟著螢幕寬度縮放**。手機橫拿，字突然變大一倍，並不是好的體驗。
要隨螢幕變化的是版面：欄寬、間距、圖片尺寸，用 `%`、`vw`、Flex／Grid 和 media query 處理，文字交給 rem。

## 例子與對比

### 拿掉 amfe-flexible

```ts
// main.ts
import 'amfe-flexible'; // [!code --]
import { createApp } from 'vue';
import App from './App.vue';

createApp(App).mount('#app');
```

```sh
pnpm remove amfe-flexible
```

### postcss-pxtorem 的設定

```js
// postcss.config.js
export default {
    plugins: {
        'postcss-pxtorem': {
            rootValue: 16, // 跟瀏覽器預設根字級一致，設計稿的 px 換算後大小不變
            propList: ['*'], // 所有屬性都換算
            minPixelValue: 2 // 1px 的邊框之類不換，避免算出太小的 rem
        }
    }
};
```

如果設計稿是 375px 寬、又想讓版面等比，`rootValue` 照樣是 16，版面的部分改用 `vw` 或 media query，不要動根字級。

### 前後對比

| | amfe-flexible + pxtorem | 只用 pxtorem |
|---|---|---|
| 根字級 | JS 寫死成 `螢幕寬 / 10` px | 瀏覽器預設，使用者可調 |
| 調大瀏覽器字級 | 沒反應 | 文字變大 |
| 頁面放大 200% | 文字大小不變 | 文字跟著放大 |
| 螢幕變寬 | 所有東西（包含文字）一起變大 | 版面用 `vw`／media query 調整，文字不變 |
| 無障礙檢測 | 文字放大這條過不了 | 可以過 |

### 順手檢查 viewport

```html
<!-- 不推薦：禁止使用者縮放，同樣是無障礙檢測的扣分項 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no">

<!-- 推薦 -->
<meta name="viewport" content="width=device-width, initial-scale=1">
```

## 結論

`amfe-flexible` 解決的是「設計稿怎麼在各種手機上長得一樣」，但它是用「把使用者的放大鏡沒收」換來的。
無障礙不是要你犧牲開發體驗：px 照寫、交給 `postcss-pxtorem` 換算，只要別讓 JS 去碰根字級就好。一個套件拿掉，換來一整群使用者看得到你的網站，這筆交易很划算。~~而且還能過審，誰不愛。~~
