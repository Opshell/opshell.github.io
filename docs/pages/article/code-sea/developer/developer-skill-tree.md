每隔一陣子就會看到「要不要刷 LeetCode」的討論：有人說面試就考這個，不刷不行；有人說工作上根本用不到。這篇不是要說刷題沒用，而是想把工程師的技能樹攤開來看：刷題點亮的是哪一格，還有哪些格子是刷題點不到的。寫給正在準備面試、或是在想「我到底還缺什麼」的工程師。

## 懶人包
- LeetCode 只是在側重演算法的實踐，它點亮的是技能樹上很重要、但只有一格的位置。
- 刷題刷得好的人，程式基本功會有一定程度，但對框架選型、特定生態系常用的工具，不一定熟。
- 系統設計、程式碼品質、測試驅動開發、框架熟悉程度、協作能力、架構設計，這些通通無法透過 LeetCode 的成績得知。
- 技能樹要均衡地點，面試官也應該用不同的方式去看不同的格子。

## 觀點拆解

### 刷題點亮的那一格
先說公道話：會刷題的人，演算法、資料結構、拆解問題的能力會有一定程度，寫起迴圈、遞迴、複雜度分析也比較有感覺。這是實打實的基本功，不是沒用。

只是這樣會變成：對於框架選型，容易遇到障礙。

### 生態系的那一格
LeetCode 的題目不會問你：「這個需求在 `Vue` 的生態系裡，通常會用什麼解？」

對於特定的 ecosystem 常用哪些工具，刷題的人也不會知道。就像我們 `Vue` 常用的其他 library，`VueUse` 這類東西，會考試的人也不一定都用過，也都是要進來以後才會慢慢熟悉。

這就像背熟了整本食譜，不代表你知道哪個市場的菜比較新鮮、哪家調味料比較順手。食譜是基本功，市場是經驗。

### 刷題點不到的那些格子
以下這些，通通無法透過 LeetCode 的成績得知：

| 技能 | 實際工作長什麼樣 | 刷題有沒有練到 |
| :--- | :--- | :--- |
| 系統設計 | 這個功能要拆成幾個服務？資料怎麼流？ | 幾乎沒有 |
| 程式碼品質 | 命名、拆分、可讀性，半年後自己還看得懂 | 沒有，題目寫完就丟 |
| TDD 測試驅動開發 | 先寫測試、再寫實作，改東西不怕壞 | 沒有，只有平台的測資 |
| 框架熟悉程度 | 生命週期、響應式、效能陷阱 | 沒有 |
| 協作能力 | Code Review、討論規格、跟後端對 API | 沒有，刷題是一個人的事 |
| 架構設計 | 資料夾怎麼放、模組怎麼切、依賴怎麼管 | 沒有 |

刷題的世界裡，輸入格式永遠清楚、需求永遠不會改、寫完就不用維護。真實的專案剛好三個都相反 ~~（尤其是需求會改這一點）~~。

### 那技能樹要怎麼點
我的看法是：把技能樹想成 RPG 的天賦樹，主線是基本功，但支線才決定你是什麼職業。

- **基本功**：語言本身、資料結構、演算法，刷題可以幫上忙。
- **生態系**：選一個框架深入，知道它的周邊工具與常見做法。
- **工程品質**：可讀性、測試、重構，這些在自己的專案裡練最有感。
- **協作與設計**：寫文件、做 Code Review、參與架構討論，這些只能在團隊裡長出來。

## 例子與對比

同樣是「實作一個搜尋框」，刷題思維跟工作思維看的東西很不一樣：

| | 刷題思維 | 工作思維 |
| :--- | :--- | :--- |
| 關心什麼 | 比對演算法的時間複雜度 | 打字時要不要 debounce、請求取消了沒 |
| 工具 | 自己從零寫 | 先看 `VueUse` 有沒有 `useDebounceFn` |
| 邊界情況 | 題目給的測資 | 中文輸入法組字中、網路慢、回應順序錯亂 |
| 寫完之後 | 提交、看排名 | 寫測試、給同事 Review、之後還要維護 |

```ts
import { useDebounceFn } from '@vueuse/core';
import { ref } from 'vue';

const keyword = ref('');
let controller: AbortController | null = null;

const search = useDebounceFn(async () => {
    // 新的搜尋開始，就取消上一個還沒回來的請求，避免回應順序錯亂
    controller?.abort();
    controller = new AbortController();

    const res = await fetch(`/api/search?q=${encodeURIComponent(keyword.value)}`, {
        signal: controller.signal
    });

    return res.json();
}, 300);
```

這段程式碼裡沒有任何一行是 LeetCode 會考的，但每一行都是實際工作會遇到的。

## 結論
LeetCode 是一把好用的磨刀石，但磨刀石不等於整把刀。刷題點亮的是基本功那一格，系統設計、程式碼品質、測試、生態系、協作、架構，這些格子要靠寫專案、跟人合作才點得亮。

所以，題目照刷，專案照寫，技能樹不要只點一條線，不然很容易變成一個攻擊力爆表、但不會走路的角色。
