::: info 這篇的脈絡
寫程式最舒服的狀態，是進入「心流」：腦袋裡同時記著五個檔案、三個變數的關係，手指跟得上思緒。最痛苦的則是剛進去就被打斷，要花很久才回得去。
時間管理的方法很多，最常被推薦的是番茄鐘，但它跟心流其實有點互相打架。這篇比較番茄鐘和它的變體 Flowmodoro，寫給一坐下來就忘記時間、或一坐下來就一直滑手機的工程師。
:::

## 懶人包
- **番茄鐘**：專注 25 分鐘、休息 5 分鐘，四輪後長休息。固定節奏，適合「很難開始」的時候。
- 番茄鐘的問題是**計時器不管你在不在心流裡**，常常在最順的時候響起。
- **Flowmodoro**：不設上限，做到自然分心才停，休息時間依專注時間比例算（常見是五分之一）。適合「一開始就停不下來」的時候。
- 兩種不用二選一：難開始的工作用番茄鐘暖機，進入狀態後改成 Flowmodoro。
- 不管哪一種，重點都是**休息是排好的**，而不是累到不行才停。

## 觀點拆解

### 心流為什麼珍貴

心流就像煮一鍋要顧火的湯：火候好不容易調好，被叫去開個門回來，可能又得從頭調一次。
寫程式的心流特別貴，因為進去前要先把一堆脈絡載入腦袋：這個函式誰在呼叫、那個狀態什麼時候會變、剛剛試過哪幾種寫法。一被打斷，這些全部清空。

所以時間管理對工程師來說，不只是「排時間」，更是**保護心流**、以及**提醒自己離開心流去休息**。

### 番茄鐘：用節奏逼自己開始

番茄鐘的規則很簡單：

1. 選一件事，計時 25 分鐘，只做這件事。
2. 時間到，休息 5 分鐘。
3. 每完成四個番茄，休息長一點（15～30 分鐘）。

它最大的價值是**降低開始的門檻**。「寫完整個功能」很可怕，「先專心 25 分鐘」就沒那麼可怕。對拖延、對不想碰的工作（例如補文件、修陳年 bug）特別有效。

但它的缺點對工程師很明顯：25 分鐘是固定的。你剛好在第 24 分鐘終於想通那個 bug，鈴聲響了。要嘛硬停，心流斷掉；要嘛無視它，那番茄鐘就形同虛設。

### Flowmodoro：讓心流決定長度

Flowmodoro（Flow + Pomodoro）把規則反過來：

1. 開始計時，不設上限。
2. 做到自然分心、或卡住了，就停下來，記下專注了多久。
3. 休息時間依專注時間的比例算，常見的建議是五分之一：專注 50 分鐘，休息 10 分鐘。

它尊重心流，不會在最順的時候打斷你；休息時間也跟付出成正比，做得久就休息得久。

缺點也很明顯：**很難開始的時候它幫不上忙**，而且容易一做就三個小時，起身才發現腰痠背痛、水也沒喝。

### 怎麼挑

我的看法是：兩種方法對付的是兩種不同的敵人。

- 敵人是「拖延」：用番茄鐘，固定的節奏逼自己動起來。
- 敵人是「停不下來」：用 Flowmodoro，至少讓休息跟專注時間掛鉤。

很多時候一天裡兩種敵人都會出現。早上要處理不想碰的工作，先用兩個番茄暖機；下午進入狀態寫功能，就切成 Flowmodoro，不要被鈴聲打斷。

## 例子與對比

| | 番茄鐘 | Flowmodoro |
|---|---|---|
| 專注時間 | 固定 25 分鐘 | 不固定，做到自然分心 |
| 休息時間 | 固定 5 分鐘，四輪後長休息 | 專注時間的一定比例（常見 1/5） |
| 對心流 | 可能在最順的時候打斷 | 不打斷 |
| 擅長對付 | 拖延、難開始 | 停不下來、忘記休息 |
| 需要的自律 | 開始時少，中途要守規則 | 開始時多，結束時要誠實 |

如果想自己做一個 Flowmodoro 計時器，核心邏輯其實只有幾行：

```ts
const BREAK_RATIO = 1 / 5; // 休息時間 = 專注時間 × 1/5

let focusStartedAt = 0;

function startFocus() {
    focusStartedAt = Date.now();
}

/** 停止專注，回傳建議的休息分鐘數 */
function stopFocus(): number {
    const focusMinutes = (Date.now() - focusStartedAt) / 60_000;
    return Math.max(1, Math.round(focusMinutes * BREAK_RATIO));
}
```

## 結論

時間管理沒有標準答案，番茄鐘和 Flowmodoro 都只是工具。重點不是嚴格遵守哪一套規則，而是知道自己現在的敵人是誰：是不想開始，還是停不下來。
