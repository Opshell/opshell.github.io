## 一、目錄與檔名（核心）

專案採用微調過的 **FSD**（Feature-Sliced Design）：依「業務功能」切資料夾，功能之間只透過入口檔互相引用。

```text
src/
 ├─ assets/                         # 字型、圖示、全域 SCSS
 ├─ features/{featureName}/         # 業務模組
 │   ├─ apis/                       # Repository：呼叫 API（五章）
 │   ├─ components/                 # 模組專用元件
 │   ├─ hooks/                      # 模組專用 composable
 │   ├─ services/                   # 抽離出來的複雜業務邏輯
 │   ├─ schemas/                    # Zod 資料層（五章）
 │   │   └─ {featureName}.schema.ts
 │   ├─ queries.ts                  # TanStack 查詢（六章）
 │   ├─ constants.ts                # 常數：選項陣列、對照表
 │   └─ index.ts                    # 模組唯一的出口
 ├─ layouts/                        # 版面大框
 ├─ pages/                          # 頁面元件
 ├─ router/
 ├─ shared/                         # 跨功能共用
 │   ├─ apis/                       # http 客戶端、queryClient
 │   ├─ components/                 # 共用 UI 元件
 │   ├─ hooks/                      # 共用 composable
 │   ├─ stores/                     # Pinia
 │   └─ utils/                      # 工具函式（zod.ts…）
 └─ types/                          # 全域型別（非 Zod）
```

- 🔧 **feature 只能從 `index.ts` 引用**：`import { ProductListPage } from '@/features/product'`。直接引用 feature 內部的檔案會被 ESLint 擋下。feature 內部之間用相對路徑。
- 👀 用不到的資料夾不用先建；但 **`schemas/` 例外**：只要有 schema，就放進 `schemas/`，即使只有一個檔案，結構才可預測。

### 檔名

| 種類 | 寫法 | 範例 | |
|---|---|---|---|
| `.vue` 元件 | PascalCase | `ProductListPage.vue`、`BaseButton.vue` | 🔧 |
| `.ts` | camelCase | `http.ts`、`queryClient.ts` | 🔧 |
| composable | `useXxx.ts` | `useSearch.ts` | 🔧 |
| schema、資料 | `{名稱}.schema.ts`、`{名稱}.data.ts` | `product.schema.ts` | 🔧 |
| 縮寫 | 只大寫第一個字母 | `ArticleToc.vue`、`useToc.ts`、`userId` | 🔧（檔名）👀（識別字） |

縮寫的規則不只是好看：`userID` 轉成 snake_case 是 `user_id`，轉回來會變成 `userId`，來回對不上（見五章的 key 轉換）。

## 二、CSS 與 SCSS（核心）

### 1. 組件化 BEM

純 BEM 在 Vue 裡會讓 `:class` 綁定又長又難讀。這裡把樣式分成「規格」與「狀態」兩種，各用一種寫法。

| 組成 | 語法 | 用途 | 範例 |
|---|---|---|---|
| **Block** | `.block` | 元件最外層 | `.info-card` |
| **Element** | `__element` | 區塊裡的子元素 | `.info-card__title` |
| **Modifier** | `--modifier` | **靜態規格**：props 決定，建立後不常變 | `.info-card--primary`、`--sm` |
| **State** | `.is-state` | **動態狀態**：互動中會變 | `.is-open`、`.is-loading` |

判斷方式：問「它是元件的**規格**，還是元件**現在的樣子**？」顏色、尺寸、形狀是規格，用 `--`；打開、載入中、錯誤是樣子，用 `is-`。

```vue
<!-- 不推薦：狀態也用 BEM，模板又長又難讀 -->
<div class="btn btn--primary" :class="{ 'btn--open': isOpen }">

<!-- 推薦 -->
<div class="btn btn--primary" :class="{ 'is-open': isOpen }">
```

- 🔧 class 只能是小寫 kebab-case 加上 `__`、`--`（stylelint `selector-class-pattern`）。覆蓋第三方元件的 class（例如 VitePress 的 `.VPNav`）時，用 `/* stylelint-disable-next-line selector-class-pattern */` 放行，並註明是誰的 class。
- 👀 `--` 與 `is-` 的分工工具判斷不了，靠 review。

### 2. 樣式包在唯一的頂層 class 裡，不用 `scoped`

```scss
.info-card {
    // 根元素自己的樣式直接寫在這裡
    display: flex;
    padding: 1rem;

    &__title { font-weight: 700; }        // Element
    &--highlight { background: yellow; }  // Modifier
    &.is-active { border: 2px solid blue; } // State：接在 Block 上，不單獨存在

    &.is-error {
        border-color: red;

        .info-card__title { color: red; } // 狀態連動子元素
    }
}
```

- 🔧 **`<style>` 不加 `scoped`**（ESLint `vue/enforce-style-attribute`）。
  `scoped` 只套得到自己寫的元素和子元件的最外層，寫到子元件內部的選擇器會**安靜地失效**：建置不報錯、畫面也不壞，就是沒作用。
  頂層 class 已經把樣式關在元件裡了，`scoped` 多出來的只剩這個風險。
- 👀 **頂層 class 要全專案唯一**。兩個元件都叫 `.hud-container`，樣式就會互相套用。
- 👀 **狀態不准單獨出現在最外層**：`.is-open { … }` 寫在最外層會影響整個專案，一律寫成 `.block.is-open`。
  這樣寫權重也比較高，蓋得過基礎樣式，不需要 `!important`。
- 👀 `<Transition>` 的 class 也收進頂層：轉場的是根元素自己就寫 `&.fade-enter-active`，是子元素就照常巢狀。
  最外層寫 `.fade-enter-active` 會套到全專案同名的轉場。
- 👀 `@keyframes` 的名稱是全域的，加元件前綴：`hud-scan`、`card-flip`。
- 🔧 不用 `:deep()`、`::v-deep()`：沒有 `scoped` 時它們不會被轉換，整條規則會被瀏覽器丟掉（跟著 `scoped` 一起被擋）。

### 3. 複雜的 class 交給 computed（ViewModel）

元件同時有好幾個 props 與狀態時，不要在模板裡拼 class：

```vue
<script setup lang="ts">
    const props = defineProps<{ type: 'main' | 'sub'; size: 'sm' | 'md' }>();
    const isOpen = ref(false);
    const hasError = ref(false);

    const containerClasses = computed(() => [
        `info-card--${props.type}`,
        `info-card--${props.size}`,
        { 'is-open': isOpen.value, 'is-error': hasError.value }
    ]);
</script>

<template>
    <div class="info-card" :class="containerClasses">…</div>
</template>
```

### 4. 其他

- 🔧 顏色用新式寫法 `rgb(0 0 0 / 15%)`，不用逗號、不用 `rgba()`（stylelint `color-function-notation: modern`，`--fix` 會自動轉）。
  stylelint 不檢查 CSS 自訂屬性（`--x: …`）與 SCSS 變數裡的值，那裡自己寫對。
- 👀 除了覆蓋套件樣式這種不得已的情況，不用 `!important`。

## 三、SFC Script 組織（核心）

### 1. 原則

1. **高內聚**：同一個功能的狀態、計算屬性、處理函式放在同一個區塊裡。
   一個區塊要做到「整塊拿掉，元件其他部分照常運作」，所以區塊之間不互相伸手去改對方的狀態。
2. **單一事實來源**：列表頁的搜尋條件以**網址**為準（URL-First）。
3. **可掃描**：用 `// #region` 分塊，在 VS Code 的大綱與麵包屑裡一眼看出元件結構。

### 2. 排列順序

| 順序 | 區塊 | 內容 |
|---|---|---|
| **01** | Imports | `import type` 在最前，再來套件、自己的模組 |
| **02** | Initializations | 路由、QueryClient、Store 等依賴 |
| **03** | Core SSoT Context | 從網址衍生的搜尋條件，與頁面主資料的查詢 |
| **04** | Feature Blocks | 一個功能一個 `#region`：搜尋、彈窗、批次操作… |
| **05** | Display Mapping | 給模板用的 `computed`（ViewModel） |
| **06** | Lifecycle | `onMounted`、`onUnmounted` |

### 3. 細則

- 👀 **region**：`// #region [P] 名稱` … `// #endregion`。`[P]` 是區塊標題的標記，SCSS 與模板（`<!-- #region [P] 名稱 -->`）也用同一個寫法。
- 👀 **命名**：`xxxHandler` 是使用者觸發的函式（`searchHandler`、`editHandler`）；`xxxExecute` 是真正打 API 或做重活的函式（`updateExecute`）。
- 👀 **緩衝搜尋**：輸入框綁 `localSearch`（緩衝區），按下搜尋才寫進網址；`searchParams` 從網址算出來、唯讀。
  網址變了（上一頁、手改網址）要把 `localSearch` 同步回來。這樣打字不會讓路由一直跳，也不會被節流。
- 👀 一個區塊超過約 150 行，抽成 composable（`useXxx.ts`）。

::: tip 為什麼是網址優先
- 按上一頁、重新整理，搜尋結果不會消失
- 把網址丟給別人，對方看到一模一樣的結果（含頁碼）
- 查詢只依賴 `searchParams` 一個來源，不用監聽一堆 `ref`
:::

### 4. 範本

下面這個範本用到了條件章（Zod、TanStack Query）；沒用這些工具的專案，照同樣的區塊順序寫就好。

::: details 展開範本：產品列表頁
```vue
<script setup lang="ts">
    /** [01] Imports
     */
    import type { UpdateProductInput } from '../schemas/product.schema';
    import { useMutation, useQuery, useQueryClient } from '@tanstack/vue-query';
    import { computed, ref, watch } from 'vue';
    import { useRoute, useRouter } from 'vue-router';
    import { productApi } from '../apis/product.api';
    import { productQueries } from '../queries';
    import { GetProductListFormSchema } from '../schemas/product.schema';

    /** [02] Initializations
     */
    const route = useRoute();
    const router = useRouter();
    const queryClient = useQueryClient();

    /** [03] Core SSoT Context
     * 網址就是搜尋狀態：上一頁、重新整理、分享網址都會得到同一個結果
     */
    const searchParams = computed(() => GetProductListFormSchema.parse(route.query));
    const { data: listData, isPending } = useQuery(productQueries.list(searchParams));

    // #region [P] 搜尋與分頁

    const localSearch = ref({ keyword: searchParams.value.keyword });

    // 網址變了（上一頁、別處改了網址）就把輸入框同步回來
    watch(searchParams, (params) => {
        localSearch.value = { keyword: params.keyword };
    });

    function searchHandler() {
        router.replace({ query: { ...route.query, ...localSearch.value, page: undefined } }); // 搜尋必重置頁碼
    }

    function pageChangeHandler(page: number) {
        router.replace({ query: { ...route.query, page: page > 1 ? page : undefined } });
    }

    // #endregion

    // #region [P] 維護彈窗

    const isModalShow = ref(false);
    const activeId = ref<number | null>(null);

    const { mutate: updateExecute, isPending: isUpdating } = useMutation({
        mutationFn: (input: UpdateProductInput) => productApi.update(input),
        onSuccess: () => {
            queryClient.invalidateQueries({ queryKey: productQueries.all() });
            isModalShow.value = false;
        }
    });

    function editHandler(id: number) {
        activeId.value = id;
        isModalShow.value = true;
    }

    // #endregion

    // #region [P] 批次操作

    const selectIds = ref<number[]>([]);

    // 換了搜尋條件，勾選就不再對應畫面上的資料：由這個區塊自己清，不讓搜尋區塊伸手進來
    watch(searchParams, () => {
        selectIds.value = [];
    });

    const { mutate: batchDeleteExecute } = useMutation({
        mutationFn: (ids: number[]) => productApi.batchDelete({ ids }),
        onSuccess: () => queryClient.invalidateQueries({ queryKey: productQueries.lists() })
    });

    function batchDeleteHandler() {
        if (!selectIds.value.length) return;
        batchDeleteExecute(selectIds.value);
    }

    // #endregion

    /** [05] Display Mapping
     */
    const displayList = computed(() => listData.value?.items.map(item => ({
        ...item,
        typeLabel: item.type === 'physical' ? '實體' : '數位'
    })) ?? []);
</script>
```

## 四、TypeScript 基本（核心）

- 👀 **型別名稱 PascalCase**，欄位 camelCase。
- 👀 **不用魔法數字**：有意義的值用字串聯集或列舉表達，不寫 `type: 1`。
- 👀 **核心實體寫 JSDoc**：說明它代表什麼、誰從它衍生。
- 👀 不用 `any` 逃避型別。真的要接第三方鬆散型別時用 `as` 並註明原因。

::: danger 待定：手寫 interface 要不要加前綴
這個部落格手寫的 interface 用 `i` 前綴（`iProps`、`iPoint`），型別別名用 `t` 前綴（`tQuery`）；
Zod 衍生的型別則是跟 Schema 同名、不加前綴（`Product`）。兩種要不要統一、統一成哪種，還沒決定。
:::

## 五、Zod 資料層（條件：專案用 Zod 4）

### 1. 核心思想

**從核心 Schema 衍生出一切。** 前端用到的資料形狀、驗證規則，都定義在一份核心 Schema 裡；
送出 API 的參數、解析 API 的回應，全部從它衍生。

目標是：看到一個 Schema 的名稱，就能回答三個問題——它的職責是什麼？資料往哪裡流（送出去還是收回來）？是原始的還是處理過的？

### 2. 設計原則

- 👀 **核心 Schema 是單一事實來源（SSoT）**。它是純粹的資料形狀與驗證規則：
  - **沒有 `.transform()`**：轉格式會讓繼承或驗證時發生隱性轉型。
  - **沒有 `.default()`**：預設值由產生資料的那一層負責（Parser 的髒活、表單的初始值）。
    而且在 Zod 4，`.pipe()` 要求後面那個 Schema 的**輸入型別**能被前面的輸出滿足；
    `.default(0)` 會讓輸入變成 `number | undefined`，Parser 接到核心 Schema 時就會型別錯誤。
  - **沒有只給 UI 用的欄位**：那些在元件裡處理，核心才能到處重用。
- 👀 **由內而外**：巢狀的 Schema 先定義最深層，再一層層組合。
- 👀 **列舉用 `z.enum()`**，取代 `z.string()` 或魔法數字；Raw 也用同一個 enum（理由見 6-3）。
- 👀 **核心 Schema 寫 JSDoc**。

### 3. 命名

Schema 與型別都用 PascalCase。後綴說明它的職責：

| 後綴 | 是什麼 | 範例 |
|---|---|---|
| `...Schema` | **核心實體**（SSoT） | `ProductSchema` |
| `...FormSchema` | UI 表單或網址搜尋條件的驗證，**沒有 `.transform()`** | `UpdateProductFormSchema`、`GetProductListFormSchema` |
| `...Params` | `GET` 的請求參數（query、path） | `GetProductListParams` |
| `...Payload` | `POST`／`PUT`／`PATCH`／`DELETE` 的請求 body | `UpdateProductPayload` |
| `...RawSchema` | 後端的原始回應（snake_case，允許 nullable），只用來衍生 Parser | `ProductItemRawSchema` |
| `...Parser` | 解析回應：Raw → 髒活 → 駝峰 → 核心 Schema | `GetProductListParser` |

從 Schema 導出的型別：

| 型別 | 產生方式 | 代表什麼 |
|---|---|---|
| `Product` | `z.infer<typeof ProductSchema>` | 核心型別。Parser 解析完的結果就是它 |
| `...Form` | `z.output<typeof ...FormSchema>` | 表單或搜尋條件驗證後的值 |
| `...Input` | `z.input<typeof ...Params／Payload>` | **呼叫 Repository 時傳入的資料**（轉換前） |
| `...Output` | `z.input<typeof ...Parser>` | **API 回傳的原始資料**（解析前） |

::: warning `...Output` 不是 `z.output`
`...Output` 指「API **輸出**給前端的原始資料」，所以用 `z.input<Parser>` 產生（Parser 的輸入就是 API 的輸出）。
它跟 Zod 的 `z.output`（轉換**後**的型別）不同；要解析後的型別，直接用核心型別（`Product`）。
:::

### 4. 檔案內的排序

1. **核心 Schema 置頂**：核心 Schema 與它的 `infer` 型別放最上面。
2. **共用的 Raw 基底與單筆 Parser**：好幾支 API 共用的放這裡。
3. **一支 API 一個 region**：`// #region [P] 取得產品列表 GET /api/products`。
4. **region 裡照「請求 → 回應 → 型別」排**：`FormSchema`／`Params`／`Payload` → `RawSchema`／`Parser` → 型別。

### 5. 送出：Params 與 Payload

從核心 Schema `.pick()`／`.omit()`／`.extend()` 出請求的形狀，最後 `.transform(camelToSnake)` 轉成後端格式。
資料要調整的（布林轉 0／1 之類），**在 snake_case 上做**。

### 6. 回應：Parser

#### 6-1. 流程

```text
RawSchema（寬鬆、snake_case）→ .transform(髒活) → .transform(snakeToCamel) → .pipe(核心 Schema)（嚴格）
```

**永遠在 snake_case 上做髒活，然後一次清洗乾淨。** `snakeToCamel` 是進入 `.pipe()` 前最後一道標準化，
寫髒活時不用去想欄位現在是哪一種命名。Raw 可以寬鬆（`nullable`、`optional`），經過 `.pipe()` 之後一定是嚴格的核心型別。

#### 6-2. 組合與別名

- 👀 **單筆 Parser 可以直接組合**：列表的 Parser 寫 `z.array(ProductItemParser)`，不要把單筆的髒活再寫一次。
- 👀 **型別別名優先**：回應結構一樣時，直接 `const UpdateProductParser = ProductItemParser`；
  需要差異才 `.extend()`／`.omit()`；兩者都不行才獨立宣告。

#### 6-3. 列舉在 Raw 也用同一個 enum

Raw 的 `type` 寫成 `z.string()` 的話，`.pipe(ProductSchema)` 時 `string` 塞不進 `'physical' | 'digital'`，型別檢查會失敗。
後端的值域跟前端一致時，Raw 直接用 `ProductTypeSchema`；不一致就在髒活裡做對照。

#### 6-4. 多餘的欄位丟掉

👀 物件一律用 `z.object()`：後端多回傳的欄位會被剝掉。後端加欄位前端不會壞，也不會不小心用到沒定義的東西。
不用 `z.looseObject()`（多的欄位原樣留著，型別卻看不到）也不用 `z.strictObject()`（後端一加欄位前端就壞）。

### 7. 網址上的搜尋條件

網址是使用者可以亂改的輸入，壞值要退回預設，不能讓頁面壞掉：

- 用 `.catch(預設值)`：解析失敗時用預設值，不丟錯。
- 布林值用 **`z.stringbool()`**：網址上的 `'false'` 會變成 `false`。
  **不要用 `z.coerce.boolean()`**：它把所有非空字串都當成 `true`，`'false'` 也是。

### 8. 解析失敗

Repository 解析回應只走一個入口 `parseResponse(schema, data, endpoint)`：

- 成功回傳解析後的資料；失敗丟出 **`ApiSchemaError`**，帶著端點與 Zod 的錯誤明細。
- 它走一般的錯誤流程：TanStack 的 `error` 狀態、畫面顯示「資料格式有誤」。
- 不重試（重試也不會變對），統一在 `QueryCache` 的 `onError` 記錄：開發時印出哪個欄位不對，正式環境交給錯誤回報（六章）。

不採用的做法：Repository 回傳 `{ success, data, error }` 讓每個呼叫端自己判斷（容易漏）；失敗時記錄但照用原始資料（型別保證等於失效）。

### 9. 其他

- 👀 `.schema.ts` 保持純粹，不 import Vue 的 `ref`、composable。驗證規則依賴畫面狀態時，用工廠函式（七章的 `createAuthFormSchema`）。
- 👀 不同情境建新的 Schema，不在同一個 Schema 上加一堆條件。

### 10. 完整範例

```ts [product.schema.ts]
import { z } from 'zod';
import { camelToSnake, snakeToCamel } from '@/shared/utils/zod';

// #region [P] 核心 SSoT

export const ProductTypeSchema = z.enum(['physical', 'digital']);

/** 產品核心實體
 * 定義產品的資料形狀與驗證規則，是所有 API 型別的衍生來源。
 * 沒有 transform、沒有 default、沒有只給 UI 用的欄位：預設值由產生資料的那一層負責（Parser、表單初始值）。
 */
export const ProductSchema = z.object({
    id: z.number().int().positive(),
    title: z.string().min(1, '名稱為必填'),
    type: ProductTypeSchema,
    sort: z.number().int(),
    parentId: z.number().int(),
    isEnabled: z.boolean()
});

export type Product = z.infer<typeof ProductSchema>;
export type ProductType = z.infer<typeof ProductTypeSchema>;

// #endregion

// #region [P] 共用 Raw 基底與單筆 Parser

/** 後端的單筆產品：snake_case、is_enabled 是 0／1、parent_id 可能是 null */
const ProductItemRawSchema = z.object({
    id: z.number(),
    title: z.string(),
    type: ProductTypeSchema, // 列舉在 Raw 也用同一個 enum：用 z.string() 的話，pipe 到核心 Schema 時型別對不上
    sort: z.number(),
    parent_id: z.number().nullable(),
    is_enabled: z.union([z.literal(0), z.literal(1)])
});

/** 單筆解析：在 snake_case 上做髒活 → 轉駝峰 → 交給核心 Schema 驗證 */
export const ProductItemParser = ProductItemRawSchema
    .transform(data => ({
        ...data,
        parent_id: data.parent_id ?? 0,
        is_enabled: data.is_enabled === 1
    }))
    .transform(snakeToCamel)
    .pipe(ProductSchema);

// #endregion

// #region [P] 取得產品列表 GET /api/products

/** 網址上的搜尋條件（URL-First 的 SSoT）。網址可以被手改，壞值退回預設，頁面不會因此壞掉 */
export const GetProductListFormSchema = z.object({
    page: z.coerce.number<unknown>().int().positive().catch(1),
    keyword: z.string().catch(''),
    isEnabled: z.stringbool().optional().catch(undefined) // 'false' 會變成 false；z.coerce.boolean() 會把它變成 true
});

export const GetProductListParams = ProductSchema
    .pick({ isEnabled: true })
    .partial()
    .extend({
        page: z.number().int().positive(),
        keyword: z.string().optional()
    })
    .transform(camelToSnake);

export const GetProductListParser = z
    .object({
        items: z.array(ProductItemParser), // 單筆 Parser 直接組合，不重寫一次
        total: z.number()
    });

// [-] Types
export type GetProductListForm = z.output<typeof GetProductListFormSchema>;
export type GetProductListInput = z.input<typeof GetProductListParams>;
export type GetProductListOutput = z.input<typeof GetProductListParser>;
export type ProductList = z.output<typeof GetProductListParser>;

// #endregion

// #region [P] 更新產品 PUT /api/products/:id

export const UpdateProductFormSchema = ProductSchema.pick({
    id: true,
    title: true,
    type: true,
    sort: true,
    isEnabled: true
});

export const UpdateProductPayload = UpdateProductFormSchema
    .transform(camelToSnake)
    .transform(data => ({
        ...data,
        is_enabled: data.is_enabled ? 1 : 0 // 在 snake_case 上做髒活
    }));

export const UpdateProductParser = ProductItemParser; // 回應結構跟單筆一樣：型別別名優先

// [-] Types
export type UpdateProductForm = z.infer<typeof UpdateProductFormSchema>;
export type UpdateProductInput = z.input<typeof UpdateProductPayload>;
export type UpdateProductOutput = z.input<typeof UpdateProductParser>;

// #endregion

// #region [P] 批次刪除 DELETE /api/products

export const BatchDeleteProductPayload = z
    .object({ ids: z.array(z.number().int().positive()).min(1, '至少選一筆') })
    .transform(camelToSnake);

export type BatchDeleteProductInput = z.input<typeof BatchDeleteProductPayload>;

// #endregion
```

## 六、伺服端資料（條件：專案用 TanStack Query v5）

### 1. 查詢集中在 feature 的 `queries.ts`

👀 用 `queryOptions()` 把 query key 與 queryFn 綁在一起，元件只寫 `useQuery(productQueries.list(searchParams))`：
key 不會拼錯，同一個查詢在不同元件裡也保證是同一份快取。

```ts
import type { MaybeRefOrGetter } from 'vue';
import type { GetProductListInput } from './schemas/product.schema';
import { queryOptions } from '@tanstack/vue-query';
import { toValue } from 'vue';
import { productApi } from './apis/product.api';

/**
 * 產品的查詢：key 與 queryFn 綁在一起，元件只寫 useQuery(productQueries.list(params))。
 * key 有階層，失效時可以整批（all）或只打一種（lists）。
 */
export const productQueries = {
    all: () => ['product'] as const,
    lists: () => [...productQueries.all(), 'list'] as const,
    list: (params: MaybeRefOrGetter<GetProductListInput>) => queryOptions({
        queryKey: [...productQueries.lists(), params],
        queryFn: () => productApi.getList(toValue(params))
    }),
    detail: (id: MaybeRefOrGetter<number>) => queryOptions({
        queryKey: [...productQueries.all(), 'detail', id],
        queryFn: () => productApi.getItem(toValue(id))
    })
};
```

key 有階層：`['product']` → `['product', 'list']` → `['product', 'list', params]`。失效時可以整批（`all()`）或只打一種（`lists()`）。
參數可以直接傳 `computed`，網址一變就自動重查。

### 2. 寫入之後：預設失效重抓

👀 mutation 成功後 `invalidateQueries({ queryKey: productQueries.all() })`，讓相關查詢重抓。

**樂觀更新**（先改畫面、再送出）是例外，只用在拖曳排序、勾選這種需要即時手感的地方，而且一定要寫失敗時怎麼還原。

### 3. 全域預設值

```ts
import { QueryCache, QueryClient } from '@tanstack/vue-query';
import { ApiSchemaError } from '@/shared/utils/zod';
import { isClientError } from './http';

/**
 * 全專案共用的 QueryClient 預設值。
 * - staleTime 30 秒：預設是 0，每次切頁面都會重抓
 * - 格式錯誤與 4xx 不重試（重試也不會變對），5xx 與網路錯誤重試 2 次
 * - 格式錯誤統一在這裡記錄：開發時印出哪個欄位不對，正式環境交給錯誤回報
 */
export function createQueryClient(report: (error: Error) => void = console.error) {
    return new QueryClient({
        queryCache: new QueryCache({
            onError: (error) => {
                if (error instanceof ApiSchemaError) report(error);
            }
        }),
        defaultOptions: {
            queries: {
                staleTime: 30_000,
                retry: (failureCount, error) =>
                    !(error instanceof ApiSchemaError)
                    && !isClientError(error)
                    && failureCount < 2
            }
        }
    });
}
```

- `staleTime` 30 秒：預設是 0，每次切頁面都會重抓。
- `ApiSchemaError` 與 4xx 不重試；5xx 與網路錯誤重試 2 次。
- 範例的 `HttpError`、`isClientError` 來自專案的 http 客戶端，重點是**失敗時要丟出帶狀態碼的錯誤**，重試規則才判斷得了。

::: danger 待定：Pinia 的角色
伺服端的資料一律交給 TanStack Query 之後，Pinia 是否只放客戶端狀態（登入者、UI 偏好），還沒明確決定。
:::

## 七、表單（條件：專案用 vee-validate）

### 1. 表單驗證與送出資料分開

表單用的 Schema 如果有 `.transform()`（例如 `camelToSnake`），表單內部的值（camelCase）跟送出的結果（snake_case）就會不一致。所以拆開：

- **`...FormSchema`**：沒有 transform，只給 `useForm` 的 `validationSchema` 做即時驗證。
- **`...Payload`**：以 FormSchema 為基礎加上 transform，在 `handleSubmit` 裡把表單值轉成送出的格式。

### 2. 表單資料和送出資料不一樣時，拆三層

需要補上表單以外的資料（例如 token）時：

```ts
import { z } from 'zod';
import { camelToSnake } from '@/shared/utils/zod';

/** 登入表單的靜態規則 */
export const AuthFormSchema = z.object({
    account: z.string().min(1, '帳號為必填'),
    password: z.string().min(6, '密碼至少 6 碼'),
    captcha: z.string().min(1, '驗證碼為必填')
});

/**
 * 要比對畫面上的驗證碼，規則依賴 UI 狀態：用工廠函式產生，.schema.ts 本身不 import Vue
 * @param captcha - 畫面上正確的驗證碼
 */
export function createAuthFormSchema(captcha: string) {
    return AuthFormSchema.refine(
        data => data.captcha.toUpperCase() === captcha.toUpperCase(),
        { error: '驗證碼錯誤', path: ['captcha'] }
    );
}

// #region [P] 登入 POST /api/login：表單資料與送出資料不一樣時，拆成三層

/** 1. 使用者輸入（View Model）：給表單綁定 */
export const AuthInputSchema = AuthFormSchema.pick({ account: true, password: true });

/** 2. 完整請求資料（Domain Model）：程式補上 token 之後的狀態 */
export const AuthRequestSchema = AuthInputSchema.extend({
    googleToken: z.string().min(1, 'Token 為必填')
});

/** 3. 最終 Payload（DTO）：轉成後端格式 */
export const AuthPayload = AuthRequestSchema.transform(camelToSnake);

// [-] Types
export type AuthInput = z.infer<typeof AuthInputSchema>;
export type AuthRequest = z.infer<typeof AuthRequestSchema>;
export type AuthPayloadOutput = z.output<typeof AuthPayload>;

// #endregion
```

### 3. 接上 vee-validate

`@vee-validate/zod` 只支援 Zod 3，所以用附錄 B 的 `toFormSchema()` 轉接（vee-validate 5 正式版支援 Standard Schema 後可以拿掉）：

```vue
<script setup lang="ts">
    import { useForm } from 'vee-validate';
    import { computed, ref } from 'vue';
    import { http } from '@/shared/apis/http';
    import { toFormSchema } from '@/shared/utils/zod';
    import { AuthPayload, createAuthFormSchema } from '../schemas/auth.schema';

    const props = defineProps<{ googleToken: string }>();
    const captchaAnswer = ref('A1B2');

    // 表單用沒有 transform 的 FormSchema；送出時才轉成 Payload
    const validationSchema = computed(() => toFormSchema(createAuthFormSchema(captchaAnswer.value)));
    const { defineField, handleSubmit, errors } = useForm({ validationSchema });
    const [account] = defineField('account');

    const submitHandler = handleSubmit(async (values) => {
        const payload = AuthPayload.parse({ ...values, googleToken: props.googleToken });
        await http.post('/api/login', payload);
    });
</script>
```

驗證規則依賴畫面狀態（這裡是畫面上的驗證碼）時，用工廠函式產生 Schema，再用 `computed` 包起來，驗證碼變了規則就跟著變。

## 附錄 A：不採用與為什麼

| 不採用 | 為什麼 | 改用 |
|---|---|---|
| `<style scoped>` | 寫到子元件內部的選擇器會安靜失效；頂層 class 已經隔離了樣式 | 唯一的頂層 class（二章） |
| 狀態也用 BEM（`.btn--open`） | 模板的 `:class` 冗長，也分不出規格和狀態 | `--` 給規格、`is-` 給狀態 |
| 核心 Schema 放 `.default()` | 在 Zod 4 會讓 `.pipe()` 型別不相容；預設值不是資料形狀的一部分 | 在 Parser 的髒活或表單初始值給預設 |
| 網址布林值用 `z.coerce.boolean()` | `'false'` 會變成 `true` | `z.stringbool()` |
| `z.looseObject()`／`z.strictObject()` | 一個讓沒定義的欄位溜進來，一個讓後端每次加欄位前端就壞 | `z.object()` |
| Repository 回傳 `safeParse` 的結果 | 每個呼叫端都要自己判斷，容易漏 | `parseResponse()` 丟 `ApiSchemaError` |
| 解析失敗時照用原始資料 | 型別保證等於失效 | 丟錯，畫面顯示錯誤 |
| query key 寫在元件裡 | 多個元件共用時容易拼錯、失效時漏掉 | `queries.ts` 的 `queryOptions()` |
| 寫入後一律手動改快取 | 要跟後端的回傳格式綁在一起，出錯難查 | 預設失效重抓，樂觀更新是有條件的例外 |
| `@vee-validate/zod` | 只支援 Zod 3 | `toFormSchema()` 轉接器 |
| 識別字縮寫全大寫（`userID`） | snake_case 來回轉換對不上（`user_id` → `userId`） | 只大寫第一個字母 |

## 附錄 B：`utils/zod.ts`

key 轉換在型別層用 [type-fest](https://github.com/sindresorhus/type-fest) 的 `CamelCasedPropertiesDeep`／`SnakeCasedPropertiesDeep`，執行層自己遞迴轉；兩邊的結果（包含數字與縮寫）有測試保證一致。

::: code-group
```ts [utils/zod.ts]
import type { CamelCasedPropertiesDeep, SnakeCasedPropertiesDeep } from 'type-fest';
import type { TypedSchema } from 'vee-validate';
import { z } from 'zod';

// #region [P] key 轉換：snake_case ⇄ camelCase（型別與執行期一起轉）

function isPlainObject(value: unknown): value is Record<string, unknown> {
    if (typeof value !== 'object' || value === null) return false;
    const proto = Object.getPrototypeOf(value);
    return proto === Object.prototype || proto === null;
}

/** 遞迴轉換物件的 key；陣列逐項處理，Date、Map 等非純物件原樣保留 */
function mapKeysDeep(value: unknown, convert: (key: string) => string): unknown {
    if (Array.isArray(value)) return value.map(item => mapKeysDeep(item, convert));
    if (!isPlainObject(value)) return value;
    return Object.fromEntries(
        Object.entries(value).map(([key, item]) => [convert(key), mapKeysDeep(item, convert)])
    );
}

const toCamel = (key: string) => key.replace(/_([a-z\d])/g, (_, char: string) => char.toUpperCase());
// 連續大寫當成一個詞（userID → user_id），跟型別層 type-fest 的結果一致
const toSnake = (key: string) => key
    .replace(/([a-z\d])([A-Z])/g, '$1_$2')
    .replace(/([A-Z]+)([A-Z][a-z])/g, '$1_$2')
    .toLowerCase();

/** 後端回應 → 前端：`parent_id` → `parentId`。放在 Parser 的 `.pipe()` 前面 */
export function snakeToCamel<T>(data: T): CamelCasedPropertiesDeep<T> {
    return mapKeysDeep(data, toCamel) as CamelCasedPropertiesDeep<T>;
}

/** 前端 → 送給後端：`isEnabled` → `is_enabled`。放在 Params／Payload 的 `.transform()` */
export function camelToSnake<T>(data: T): SnakeCasedPropertiesDeep<T> {
    return mapKeysDeep(data, toSnake) as SnakeCasedPropertiesDeep<T>;
}

// #endregion

// #region [P] 解析失敗

/** 後端回傳的格式跟 Parser 對不上。帶著端點與 Zod 的錯誤明細，走一般的錯誤流程 */
export class ApiSchemaError extends Error {
    override readonly name = 'ApiSchemaError';

    constructor(readonly endpoint: string, readonly zodError: z.ZodError) {
        super(`回應格式不符（${endpoint}）\n${z.prettifyError(zodError)}`, { cause: zodError });
    }
}

/** Repository 解析回應的唯一入口：成功回傳解析後的資料，失敗丟 ApiSchemaError */
export function parseResponse<T extends z.ZodType>(schema: T, data: unknown, endpoint: string): z.output<T> {
    const result = schema.safeParse(data);
    if (!result.success) throw new ApiSchemaError(endpoint, result.error);
    return result.data;
}

// #endregion

// #region [P] vee-validate 轉接器

/**
 * 把 Zod 4 schema 交給 vee-validate 的 `validationSchema`。
 * `@vee-validate/zod` 只支援 Zod 3；vee-validate 5 正式版支援 Standard Schema 之後，這個轉接器可以拿掉。
 */
export function toFormSchema<T extends z.ZodType>(schema: T): TypedSchema<z.input<T>, z.output<T>> {
    return {
        __type: 'VVTypedSchema',
        async parse(values) {
            const result = await schema.safeParseAsync(values);
            if (result.success) return { value: result.data, errors: [] };

            const byPath = new Map<string, string[]>();
            for (const issue of result.error.issues) {
                const path = issue.path.map(String).join('.');
                byPath.set(path, [...(byPath.get(path) ?? []), issue.message]);
            }
            return { errors: [...byPath].map(([path, errors]) => ({ path, errors })) };
        }
    };
}

// #endregion
```

// 範例用的最小 HTTP 客戶端。專案裡換成自己的（axios、ofetch…），重點是：
// 失敗時丟出帶狀態碼的錯誤，讓 QueryClient 分辨要不要重試
export class HttpError extends Error {
    override readonly name = 'HttpError';

    constructor(readonly status: number, readonly endpoint: string) {
        super(`HTTP ${status}（${endpoint}）`);
    }
}

/** 4xx：請求本身有問題，重試也不會變對 */
export const isClientError = (error: unknown) =>
    error instanceof HttpError && error.status >= 400 && error.status < 500;

type tQuery = Record<string, string | number | boolean | undefined>;

async function request(method: string, url: string, options: { query?: tQuery; body?: unknown } = {}): Promise<unknown> {
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(options.query ?? {})) {
        if (value !== undefined) search.set(key, String(value));
    }
    const endpoint = `${method} ${url}`;
    const response = await fetch(search.size ? `${url}?${search}` : url, {
        method,
        headers: { 'Content-Type': 'application/json' },
        body: options.body === undefined ? undefined : JSON.stringify(options.body)
    });
    if (!response.ok) throw new HttpError(response.status, endpoint);
    return response.status === 204 ? undefined : response.json();
}

export const http = {
    get: (url: string, query?: tQuery) => request('GET', url, { query }),
    post: (url: string, body: unknown) => request('POST', url, { body }),
    put: (url: string, body: unknown) => request('PUT', url, { body }),
    delete: (url: string, body?: unknown) => request('DELETE', url, { body })
};
