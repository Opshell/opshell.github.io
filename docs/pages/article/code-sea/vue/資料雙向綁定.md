「Vue 有雙向綁定，React 沒有」是很常聽到的一句話，常見的情況是新手聽完就以為子元件可以直接改父元件的資料，然後在子元件裡對 prop 賦值，被 Vue 警告一臉。這篇把 `v-model` 拆開來看，寫給會用 `v-model`、但沒想過它背後是什麼的人。

參考：https://vocus.cc/article/6659ef25fd89780001f95e3e

## 懶人包

- 「雙向綁定」講的是**畫面和資料互相同步**：資料改了畫面跟著變，使用者在畫面上輸入，資料也跟著變。
- `v-model` 是語法糖：-|一個值往下傳、一個事件往上丟|-，Vue 的資料流本質上還是單向的。
- 原生元素上，它依元素類型展開成 `value` + `input`、`checked` + `change` 等組合。
- 元件上，它展開成 `modelValue` prop + `update:modelValue` 事件；Vue 3.4 之後用 `defineModel()` 一行搞定子元件那一側。
- 子元件永遠不要直接改 prop，要改就 emit 讓父層改。

## 技術拆解

### 雙向綁定是哪兩個方向

第一個方向是「資料 → 畫面」：響應式資料變了，畫面重新渲染。這是 Vue 響應式系統的本業，Vue 2 用 `Object.defineProperty`、Vue 3 用 `Proxy` 攔截讀寫來做到。

第二個方向是「畫面 → 資料」：使用者在 `input` 打字，資料要跟著更新。這件事響應式系統不會自動幫你做，靠的是**監聽事件，再把值寫回去**。

`v-model` 就是把這兩個方向打包成一個指令。

### 原生元素上的 v-model

```vue
<input v-model="keyword" />

<!-- 大致等於 -->
<input :value="keyword" @input="keyword = ($event.target as HTMLInputElement).value" />
```

不同元素綁的東西不一樣：

| 元素 | 綁的屬性 | 聽的事件 |
|---|---|---|
| `input`（文字）、`textarea` | `value` | `input` |
| `input[type=checkbox]`、`radio` | `checked` | `change` |
| `select` | `value` | `change` |

修飾符也是在這一層作用：`.lazy` 改聽 `change`、`.number` 轉數字、`.trim` 去頭尾空白。

### 元件上的 v-model

用在自己寫的元件上，Vue 3 把它展開成固定的一組 prop 和事件：

```vue
<SearchInput v-model="keyword" />

<!-- 等於 -->
<SearchInput :model-value="keyword" @update:model-value="value => keyword = value" />
```

子元件要做的事就是：拿 `modelValue` 來顯示，使用者改了就 emit `update:modelValue`。真正改資料的，還是父元件。

這就是為什麼說它「其實是單向的」：資料只從父往子流，子元件只能「請求」父元件改，不能自己動手。~~(雙向綁定，其實是父母說了算。)~~

## 例子與對比

### 子元件的寫法：手寫 props / emit

```vue
<!-- SearchInput.vue -->
<script setup lang="ts">
defineProps<{ modelValue: string }>();
const emit = defineEmits<{ 'update:modelValue': [value: string] }>();

function onInput(event: Event) {
    emit('update:modelValue', (event.target as HTMLInputElement).value);
}
</script>

<template>
    <input :value="modelValue" @input="onInput" />
</template>
```

### 子元件的寫法：defineModel（Vue 3.4+）

```vue
<!-- SearchInput.vue -->
<script setup lang="ts">
const model = defineModel<string>({ required: true });
</script>

<template>
    <input v-model="model" />
</template>
```

`defineModel()` 回傳一個 ref，讀它就是讀 `modelValue`，寫它就會 emit `update:modelValue`，編譯後跟上面手寫的版本是同一回事。多個 `v-model`、修飾符這些細節，另外寫在 `defineModel` 那篇。

### 常見的錯：直接改 prop

```vue
<script setup lang="ts">
const props = defineProps<{ modelValue: string }>();

function clear() {
    props.modelValue = ''; // 錯：prop 是唯讀的，Vue 會警告，而且父層的資料不會變
}
</script>
```

要清空，就 `emit('update:modelValue', '')`，或者用 `defineModel` 的話 `model.value = ''`。

| 寫法 | 誰改資料 | 父層會同步嗎 |
|---|---|---|
| 子元件直接改 prop | 子元件（被擋下） | 不會，還會有警告 |
| emit `update:modelValue` | 父元件 | 會 |
| `defineModel` 寫入 | 父元件（幫你 emit） | 會 |

## 結論

`v-model` 讓表單寫起來像雙向綁定，但拆開來永遠是「值往下、事件往上」。記住這件事，子元件就不會想去改 prop，元件之間的資料流也會清清楚楚。

雙向綁定是給寫程式的人看的糖衣，單向資料流才是裡面那顆藥。
