::: info 這篇的脈絡
後台系統、醫療或金融相關的系統，常見的需求是「使用者閒置超過 N 分鐘就自動登出」，避免有人離開座位後，畫面被路過的人看光光。這個功能看起來只是一個 `setTimeout`，但「什麼算操作」「多個分頁怎麼辦」「離開頁面要不要清掉」都是坑。這篇用 composable 把它收乾淨，寫給要實作這個需求的人。
:::

## 懶人包
- 核心只有一句話：-|監聽使用者操作，每次操作就重設計時器，時間到就登出|-。
- 監聽的事件要節流，不然 `mousemove` 一秒觸發幾十次，計時器一直被砍掉重建。
- 開了多個分頁時，要用 `BroadcastChannel` 或 `localStorage` 同步「最後操作時間」，不然 A 分頁在用、B 分頁把你登出。
- 用 VueUse 的 `useIdle` 可以省很多事；自己寫的話記得在 `onScopeDispose` 清掉監聽與計時器。
- 前端的閒置登出只是體驗，真正的安全還是靠後端 token 過期。

## 技術拆解

### 什麼算「有在操作」
常見會監聽的事件：`mousemove`、`mousedown`、`keydown`、`touchstart`、`wheel`，再加上 `visibilitychange`（切回分頁時檢查一下是不是已經超時）。

`mousemove` 和 `wheel` 觸發非常頻繁，每次都重設計時器沒必要，節流到一秒一次就很夠。

### 計時器怎麼設計
有兩種做法：

1. **每次操作重設 `setTimeout`**：直覺，但瀏覽器會把背景分頁的計時器延遲執行，電腦睡眠後時間也不準。
2. **記錄最後操作時間，定期檢查**：每隔幾秒用 `Date.now() - lastActive` 判斷有沒有超時。背景分頁延遲了也沒關係，回來第一次檢查就會發現超時。

第二種比較耐操，也比較好做多分頁同步，下面的範例用它。

### 多個分頁
同一個網站開三個分頁很常見。如果每個分頁各算各的，你在 A 分頁打字打得很認真，B 分頁閒置時間到了，一登出就清掉 token，A 分頁也跟著陣亡。

解法是把「最後操作時間」廣播出去：任何一個分頁有操作，所有分頁都更新 `lastActive`。`BroadcastChannel` 是最直接的工具，主流瀏覽器都支援。

### 清理
composable 裡掛了全域事件和 `setInterval`，元件卸載時沒清掉，就會在背景繼續跑，最後變成「登出頁也在倒數登出」。用 `onScopeDispose` 清理，它在元件卸載或 effect scope 停止時都會執行。

## 例子與對比

### 自己寫一個 useIdleLogout
```ts
// composables/useIdleLogout.ts
import { onScopeDispose, ref } from 'vue';

type IdleLogoutOptions = {
    timeout: number; // 閒置多久登出（毫秒）
    onTimeout: () => void; // 時間到要做的事
    checkInterval?: number; // 多久檢查一次（毫秒）
};

const ACTIVITY_EVENTS = ['mousemove', 'mousedown', 'keydown', 'touchstart', 'wheel'] as const;

export const useIdleLogout = (options: IdleLogoutOptions) => {
    const { timeout, onTimeout, checkInterval = 5000 } = options;

    const lastActive = ref(Date.now());
    const channel = new BroadcastChannel('idle-logout');
    let lastBroadcast = 0;
    let isTimedOut = false;

    // 有操作：更新時間，節流後通知其他分頁
    const markActive = () => {
        const now = Date.now();
        lastActive.value = now;

        if (now - lastBroadcast > 1000) {
            lastBroadcast = now;
            channel.postMessage(now);
        }
    };

    // 其他分頁有操作，同步過來
    channel.onmessage = (event: MessageEvent<number>) => {
        lastActive.value = Math.max(lastActive.value, event.data);
    };

    const check = () => {
        if (isTimedOut) { return; }

        if (Date.now() - lastActive.value >= timeout) {
            isTimedOut = true;
            onTimeout();
        }
    };

    const onVisibilityChange = () => {
        if (document.visibilityState === 'visible') { check(); }
    };

    ACTIVITY_EVENTS.forEach((name) => window.addEventListener(name, markActive, { passive: true }));
    document.addEventListener('visibilitychange', onVisibilityChange);
    const timer = window.setInterval(check, checkInterval);

    onScopeDispose(() => {
        ACTIVITY_EVENTS.forEach((name) => window.removeEventListener(name, markActive));
        document.removeEventListener('visibilitychange', onVisibilityChange);
        window.clearInterval(timer);
        channel.close();
    });

    return { lastActive };
};
```

掛在登入後才會出現的版面元件裡：

```vue
<!-- layouts/AdminLayout.vue -->
<script setup lang="ts">
import { useRouter } from 'vue-router';
import { useIdleLogout } from '@/composables/useIdleLogout';
import { useUserStore } from '@/stores/user';

const router = useRouter();
const userStore = useUserStore();

useIdleLogout({
    timeout: 15 * 60 * 1000,
    onTimeout: async () => {
        await userStore.signOut();
        await router.push({ name: 'Login', query: { reason: 'idle' } });
    }
});
</script>

<template>
    <RouterView />
</template>
```

掛在 layout 而不是 `App.vue`，登入頁就不會有人在背後倒數。

### 用 VueUse 的 useIdle
不需要多分頁同步的話，VueUse 已經幫你包好了：

```vue
<script setup lang="ts">
import { useIdle } from '@vueuse/core';
import { watch } from 'vue';

const { idle } = useIdle(15 * 60 * 1000);

watch(idle, (isIdle) => {
    if (isIdle) {
        // 登出
    }
});
</script>
```

| | 自己寫 | VueUse `useIdle` |
|---|---|---|
| 程式碼量 | 多 | 幾行 |
| 多分頁同步 | 自己加 `BroadcastChannel` | 要自己補 |
| 背景分頁準確度 | 用時間差判斷，準 | 以官方文件的實作為準 |
| 依賴 | 無 | 要裝 `@vueuse/core` |

### 別忘了後端
前端的閒置登出擋得住路過的同事，擋不住會開 devtools 的人。token 本身要有合理的過期時間，後端也要能撤銷 session，這才是真的安全。

## 結論
閒置登出的本質是一個會自己清理的計時器，難的是邊界情況：節流、背景分頁、多分頁、卸載清理。把這些收進一個 composable，頁面只需要說「15 分鐘、時間到做這件事」就好。
