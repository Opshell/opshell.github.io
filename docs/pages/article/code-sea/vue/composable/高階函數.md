::: info 這篇的脈絡
手動驗證表單、控制按鈕的 `disabled`、決定某個開關要不要打開，常見的情況是條件一路長成 `if (xxx === 0 || xxx === 1 && xxx < 3)`，三個月後連自己都看不懂。這篇整理我常用來避免程式碼耦合過多的做法：用高階函式產生可組合的驗證器。寫給正在跟一長串條件奮鬥的人。
:::

## 懶人包
- 高階函式就是「吃函式或吐函式」的函式，拿來把「規則」和「檢查」分開。
- 每個規則寫成一個小函式（`notEmpty`、`notZero`），放在同一個物件裡，要加條件就在這裡加。
- `every` 是全部條件都要成立，`some` 是符合其一即可。
- 不一定要包成 `computed`，寫成一般的 function 也可以；要在 template 裡響應式更新才用 `computed`。

## 技術拆解

### 問題：條件和邏輯黏在一起
```ts
if (name.trim() !== '' && (age !== 0 || type === 1 && age < 3)) {
    // ...
}
```

這種寫法的問題不是「長」，而是規則散落在每個 `if` 裡：同一個「不能空白」可能在五個地方各寫一次，改規則就要改五次，而且 `&&` 和 `||` 的優先順序一不小心就會出錯。

### 高階函式：先做出「驗證器工廠」
```ts
const createValidators = (validators) => (value) => validators.every((validator) => validator(value));
```

這一行讀起來是：給我一組規則，我回傳一個新函式；新函式拿到值之後，檢查它是不是**每一條**規則都過。

規則本身集中在一個物件裡：

```ts
const validators = {
    notEmpty: (value) => value.trim() !== '',
    notZero: (value) => value !== 0
};
```

-|你要增加條件特性的話，就在這段加|-，其他地方完全不用動。

### every 與 some
- `every`：所有條件都要成立（AND）。
- `some`：符合其一就好（OR）。

把 `createValidators` 裡的 `every` 換成 `some`，就得到一個「任一規則通過即可」的版本。兩種組合方式疊起來，就能表達大部分的開關邏輯，而不用手寫括號地獄。

## 例子與對比

### 原本的筆記版本
這是我原本的寫法（只修了 `notzero` 的拼字，原本寫成小寫 z，執行時會是 `undefined` 然後炸掉）：

```ts
// 高階函數：生成通用驗證器
const createValidators = (validators) => (value) => validators.every((validator) => validator(value));
const validators = {
    notEmpty: (value) => value.trim() !== '',
    notZero: (value) => value !== 0
};

// 檢查表單是否有效的計算屬性
const checkFormValid = computed(() => {
    const validations = [
        // 基本條件
        createValidators([validators.notEmpty])(conditionA),
        createValidators([validators.notZero])(conditionB),

        // 所有表單內依賴 A 條件的資料不為空
        form.every((value) => createValidators([validators.notEmpty])(value)),
        // 所有表單內依賴 B 條件的資料不為零
        form.every((value) => createValidators([validators.notZero])(value))
    ];

    // 檢查所有條件是否滿足
    return validations.every((validation) => validation);
});
```

### 補上型別、可以直接跑的版本
```vue
<script setup lang="ts">
import { computed, ref } from 'vue';

type Validator<T> = (value: T) => boolean;

// 全部規則都要過
const all = <T>(rules: Validator<T>[]): Validator<T> => (value) => rules.every((rule) => rule(value));
// 任一規則過就好
const any = <T>(rules: Validator<T>[]): Validator<T> => (value) => rules.some((rule) => rule(value));

// 要加條件就在這裡加
const rules = {
    notEmpty: (value: string) => value.trim() !== '',
    notZero: (value: number) => value !== 0,
    isEmail: (value: string) => /^[^\s@]+@[^\s@]+$/.test(value)
};

const name = ref('');
const contact = ref('');
const amount = ref(0);
const items = ref<string[]>(['']);

const isNameValid = all([rules.notEmpty]);
// 聯絡方式：不能空白，而且要是 email 或至少 8 碼
const isContactValid = all<string>([
    rules.notEmpty,
    any<string>([rules.isEmail, (value) => value.length >= 8])
]);

const isFormValid = computed(() => [
    isNameValid(name.value),
    isContactValid(contact.value),
    rules.notZero(amount.value),
    items.value.every(isNameValid)
].every(Boolean));
</script>

<template>
    <button type="submit" :disabled="!isFormValid">送出</button>
</template>
```

| | 一長串 if | 可組合的驗證器 |
|---|---|---|
| 加一個規則 | 找出所有相關的 if 一個個改 | 在 `rules` 加一行 |
| 讀懂條件 | 要在腦中算 `&&`／`||` 優先順序 | `all`、`any` 名字就說明了 |
| 重複使用 | 複製貼上 | 同一個驗證器到處用 |
| 單元測試 | 要整個元件掛起來測 | 每個規則都是純函式，直接測 |

### 不一定要 computed
`computed` 適合「要在 template 裡跟著資料自動更新」的情況，例如按鈕的 `disabled`。如果只是送出前檢查一次，寫成一般函式就好：

```ts
const validateBeforeSubmit = (): boolean => isNameValid(name.value) && rules.notZero(amount.value);
```

## 結論
高階函式聽起來很學術，用起來其實就是「把規則做成積木，再決定要用 AND 還是 OR 疊起來」。條件一多，這個小小的抽象就會讓你少掉很多括號、也少掉很多半夜 debug。
