官網、活動頁常常要掛一堆外部資源：分析工具、客服聊天、廣告追蹤碼、地圖、字型。每加一個，頁面就慢一點，最後檢測報告一片紅。這篇的重點就是原本筆記裡那兩句：你有很多外部資源需要載入的話，多利用一下 `async` 或 `defer` 屬性；CDN 也要配置。
:::

## 懶人包
- 一般的 `<script>` 會讓瀏覽器停下來等它下載、執行，HTML 解析整個卡住。
- `defer`：背景下載，等 HTML 解析完照順序執行，適合大部分自己的程式。
- `async`：背景下載，下載完立刻執行、不管順序，適合獨立的第三方工具（分析、廣告）。
- `type="module"` 預設就是 `defer` 的行為。
- 靜態資源放 CDN，配好快取與 `preconnect`；第三方 CDN 的 script 加 `integrity` 防被竄改。

## 技術拆解

### 一般的 script 為什麼會卡
瀏覽器讀 HTML 是由上往下的。遇到 `<script src>`，它會停下來：下載、執行，完成之後才繼續往下讀。就像在餐廳點餐，服務生每記一道菜就跑去廚房等它煮好，再回來記下一道。

這就是以前大家把 script 放在 `</body>` 前面的原因：至少讓畫面先出來。

### defer：記完菜再一起送
```html
<script defer src="/js/app.js"></script>
<script defer src="/js/analytics-setup.js"></script>
```

- 下載在背景進行，不會卡住 HTML 解析。
- 等整份 HTML 解析完，-|照寫的順序|-執行。
- 在 `DOMContentLoaded` 之前跑完。

適合：自己的程式、彼此有相依順序的程式、需要操作 DOM 的程式。

### async：誰先好誰先上
```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXX"></script>
```

- 一樣背景下載。
- 下載完就立刻執行，執行時會短暫打斷 HTML 解析。
- 多個 `async` 之間的順序不保證。

適合：完全獨立、不依賴其他程式、也沒人依賴它的第三方工具。

### type="module"
```html
<script type="module" src="/js/main.js"></script>
```

模組腳本預設就是 `defer` 的行為，不用再寫。Vite 打包出來的入口就是這種形式。如果想讓模組像 `async` 一樣下載完就跑，可以加上 `async`。

### preload 與 preconnect
`async`／`defer` 解決的是「不要卡住」，`preload`、`preconnect` 解決的是「早點開始」：

```html
<!-- 提早跟第三方網域建立連線（DNS、TCP、TLS） -->
<link rel="preconnect" href="https://cdn.example.com" crossorigin>

<!-- 這個資源一定會用到，現在就開始下載 -->
<link rel="preload" href="/fonts/NotoSansTC-Regular.woff2" as="font" type="font/woff2" crossorigin>
```

`preload` 不要亂用：預載太多東西，等於每樣都插隊，結果大家一起慢。只留給首屏一定會用到、又被藏在 CSS 裡比較晚才會被發現的資源（字型、首屏背景圖）。

### CDN 也要配置
CDN 的概念是把靜態檔案放到離使用者近的節點，台灣的使用者從台灣附近的機房拿檔案，不用跨海去美國。配置時要注意：

- **快取**：檔名帶 hash 的資源（Vite 預設就會）可以設很長的快取，例如 `Cache-Control: public, max-age=31536000, immutable`；HTML 本身則要設短，才能讓新版本即時生效。
- **壓縮**：確認有開 Brotli 或 gzip。
- **安全**：引用第三方 CDN 的 script，加上 `integrity`，萬一檔案被竄改，瀏覽器會拒絕執行。

```html
<script
    src="https://cdn.jsdelivr.net/npm/some-lib@1.2.3/dist/some-lib.min.js"
    integrity="sha384-（依檔案內容產生的雜湊）"
    crossorigin="anonymous"
    defer
></script>
```

版本號要寫死，`@latest` 加 `integrity` 的話，一更新雜湊就對不上了。

## 例子與對比

### 三種寫法一次比

| | 一般 | `defer` | `async` |
|---|---|---|---|
| 下載時卡住 HTML | 會 | 不會 | 不會 |
| 執行時機 | 下載完立刻 | HTML 解析完 | 下載完立刻 |
| 多個之間的順序 | 照順序 | 照順序 | 不保證 |
| 適合 | 幾乎沒有 | 自己的程式 | 獨立的第三方工具 |

### 一個活動頁的 head
```html
<head>
    <meta charset="UTF-8">
    <title>年末活動</title>

    <link rel="preconnect" href="https://cdn.example.com" crossorigin>
    <link rel="preload" href="/fonts/brand.woff2" as="font" type="font/woff2" crossorigin>
    <link rel="stylesheet" href="/css/main.css">

    <!-- 自己的程式：defer，照順序 -->
    <script defer src="/js/vendor.js"></script>
    <script defer src="/js/main.js"></script>

    <!-- 分析工具：async，誰也不等 -->
    <script async src="https://analytics.example.com/tag.js"></script>
</head>
```

至於客服聊天、地圖這種不是一進來就需要的東西，更好的做法是等使用者捲到、或點了才載入，連 `async` 都不用。

## 結論
外部資源載入的心法就是：-|不要讓不重要的東西擋住重要的東西|-。自己的程式 `defer`，獨立的第三方 `async`，非必要的延後載入，靜態檔案交給 CDN 並設好快取。

頁面就像一場派對，重要的客人走正門，其他的請從側門慢慢進來。
