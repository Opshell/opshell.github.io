::: info 這篇的脈絡
寫元件寫久了，很容易整頁都是 `<div class="xxx">`，畫面一樣能動，CSS 一樣能套。問題是瀏覽器、螢幕閱讀器、搜尋引擎看到的只是一堆沒有意義的盒子。這篇整理常用的語義標籤怎麼選，跟同目錄的〈無障礙〉是一組的：語義標籤是地基，ARIA 是補洞。
:::

## 懶人包
- 語義標籤讓 HTML 自己說出「這塊是什麼」，閱讀器能跳著讀、搜尋引擎抓得到重點、接手的人一眼看懂結構。
- 版面骨架：`<header>`、`<nav>`、`<main>`、`<aside>`、`<footer>`，`<main>` 一頁只能有一個。
- `<article>` 是可以單獨拿出去也看得懂的內容；`<section>` 是有標題的一個段落；只是為了排版就用 `<div>`。
- 會換頁的用 `<a>`，會在原地做事的用 `<button>`。
- 標題 `<h1>`～`<h6>` 照層級寫，不要因為字的大小挑標題。

## 技術拆解

### 為什麼要在意
用 `<div>` 堆出來的頁面，像一本沒有目錄、沒有章節標題的書：字都在，但只能從頭讀到尾。語義標籤就是在幫這本書加目錄。

具體來說有三個受益者：

1. **螢幕閱讀器的使用者**：可以直接跳到「主要內容」、「導覽」，或依標題快速瀏覽，不用聽完整個 header 才找到正文。
2. **搜尋引擎**：比較容易判斷頁面的主要內容在哪、哪些是重複的導覽和頁尾。
3. **接手的工程師**：`<nav>` 比 `<div class="nav-wrapper-outer">` 好懂太多了。

### 版面骨架
```html
<body>
    <header>
        <a href="/">網站 Logo</a>
        <nav aria-label="主選單">
            <ul>
                <li><a href="/article/">文章</a></li>
                <li><a href="/about/">關於</a></li>
            </ul>
        </nav>
    </header>

    <main>
        <!-- 這一頁獨有的主要內容 -->
    </main>

    <aside>
        <!-- 側欄：相關文章、標籤 -->
    </aside>

    <footer>
        <p>&copy; 2026 Opshell</p>
    </footer>
</body>
```

- `<header>`、`<footer>`：不只能用在整頁，文章、卡片也可以有自己的 header 和 footer。
- `<nav>`：主要的導覽區塊。不是所有連結群組都要包 `<nav>`，頁尾那排「隱私權政策、聯絡我們」用普通的列表就好。一頁有多個 `<nav>` 時，用 `aria-label` 區分。
- `<main>`：這一頁的主要內容，-|一頁只能有一個|-（隱藏的不算）。
- `<aside>`：跟主要內容相關、但拿掉也不影響理解的東西。

### article、section、div 怎麼選
這三個最容易混用，可以問自己三個問題：

```
這塊內容單獨拿出去（轉貼、放進 RSS），別人看得懂嗎？
├─ 看得懂 → <article>（文章、留言、商品卡片）
└─ 看不懂 → 這塊有自己的標題嗎？
              ├─ 有 → <section>
              └─ 沒有，只是為了排版或套樣式 → <div>
```

`<section>` 不是比較高級的 `<div>`。沒有標題的 `<section>` 在語意上沒什麼意義，那就老老實實用 `<div>`。

### 會換頁的用 a，會做事的用 button

| | `<a href>` | `<button>` |
|---|---|---|
| 用途 | 去別的地方（換頁、錨點） | 在原地做事（送出、開彈窗、切換） |
| 鍵盤 | Enter 觸發 | Enter 和空白鍵都能觸發 |
| 右鍵、中鍵 | 可以開新分頁 | 不行 |

最常見的錯誤是 `<a href="#" @click.prevent="openDialog">`：它不換頁，該是按鈕；反過來，用 `<button @click="router.push('/about')">` 做導覽，使用者就沒辦法中鍵開新分頁。Vue Router 的 `<RouterLink>` 最後渲染出來就是 `<a>`，導覽用它就對了。

### 標題要照層級
```html
<!-- 錯：因為想要小一點的字就跳到 h4 -->
<h1>文章標題</h1>
<h4>第一段</h4>

<!-- 對：層級照結構，大小交給 CSS -->
<h1>文章標題</h1>
<h2 class="section-title--small">第一段</h2>
```

閱讀器使用者很常用標題來瀏覽頁面，層級亂跳就像目錄從第一章直接跳到 1.2.3.1 節。

## 例子與對比

### 同一張卡片，兩種寫法
```html
<!-- div 版 -->
<div class="card">
    <div class="card__img"><img src="/cover.jpg"></div>
    <div class="card__title">CSS 變數改主題</div>
    <div class="card__date">2026/10/05</div>
    <div class="card__more" onclick="location.href='/post/1'">閱讀更多</div>
</div>

<!-- 語義版 -->
<article class="card">
    <img class="card__img" src="/cover.jpg" alt="">
    <h3 class="card__title">
        <a href="/post/1">CSS 變數改主題</a>
    </h3>
    <time class="card__date" datetime="2026-10-05">2026/10/05</time>
</article>
```

畫面可以長得一模一樣，但語義版：閱讀器知道這是一篇文章、標題是什麼、日期是機器看得懂的格式，連結可以用鍵盤點、可以開新分頁。

### 幾個容易忽略的小標籤

| 標籤 | 用途 |
|---|---|
| `<time datetime>` | 日期時間，`datetime` 給機器讀 |
| `<figure>` + `<figcaption>` | 圖片（或程式碼、圖表）加上說明 |
| `<address>` | 聯絡資訊 |
| `<mark>` | 標記重點、搜尋結果的關鍵字 |
| `<dl>`、`<dt>`、`<dd>` | 名詞與解釋、規格表這種「標籤：值」的清單 |
| `<details>` + `<summary>` | 原生的展開收合，不用 JavaScript |

### Vue 元件的根元素
寫元件時，根元素很容易隨手寫 `<div>`。花一秒想一下這個元件是什麼：文章卡片用 `<article>`、側欄用 `<aside>`、表單元件用 `<form>` 或 `<fieldset>`。元件化不代表要放棄語意，反而因為重複使用，用對一次就處處都對。

## 結論
語義標籤不是什麼進階技巧，是 HTML 本來的樣子。`<div>` 沒有錯，它就是那個「沒有特別意義的盒子」，錯的是所有東西都用它裝。

寫 HTML 就像整理衣櫃，每個抽屜都貼標籤，找東西的人（不管是人還是爬蟲）都會感謝你。
