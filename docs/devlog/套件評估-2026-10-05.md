## 三、建議換掉的

### 3-1 `vite-plugin-svg-icons` 2.0.1 → `vite-plugin-svg-icons-ng`

| | `vite-plugin-svg-icons`（現在） | `vite-plugin-svg-icons-ng` | `unplugin-icons` |
|---|---|---|---|
| 最後發版 | **2022-05**（停更 3 年多） | 2026-09 | 2026-09 |
| 用法 | `virtual:svg-icons-register` ＋ `<use href="#icon-x">` sprite | **跟現在一樣**（fork 出來的，API 相容） | 每個 icon 變成元件 `<IconXxx />`，要改所有用到的地方 |
| 拉進來的舊東西 | `svgo` 2.8.0、`svg-baker`→`micromatch`→舊 `braces`（`pnpm audit` 的 high 有 2 個來自它） | svgo 4 | 用 Iconify |
| 改動量 | — | `config.mts` 換 import 名稱，`ElSvgIcon` 不動 | 大：`<ElSvgIcon name="x">` 全面改寫 |

**建議 `-ng`**：幾乎零改動就擺脫停更套件。`unplugin-icons` 比較現代，但我們的 icon 是自己的 `public/icons/*.svg`，換過去收益不大、改動很大。

### 3-2 不蒜子（busuanzi）→ 自家後端

不是 npm 套件（`theme/index.ts` 動態插 `<script>`），但它是這個站唯一還在載的第三方計數。

- **它現在已經壞了**：2026-10-05 實測，腳本本身載得到（200），但計數 API `busuanzi.ibruce.info/busuanzi` 回 **502**。站上的瀏覽數都停在 `--`。
- 每頁從中國 CDN 載一支外部腳本（09-27 評估報告第 8 項：效能／隱私）。
- 它直接改 DOM 的 `innerText`，Vue 抓不到，所以 `AsideWidget.vue` 用每 2 秒輪詢的繞法——而且**繞錯了**：它讀 `busuanzi_value_site_pv_hidden`，不蒜子只會填 `busuanzi_value_site_pv`，所以側欄的 Views／Visitors 就算不蒜子活著也永遠是空的。
- 舊數字**撈不回來**（API 502），換系統等於從 0 開始；若想接上，使用者記得大概的總數，可以給後端一個起始值（見第九節）。

設計見第九節。

## 四、有新版但現在不能升的

這三個都卡在同一條鏈：**VitePress 1.6 綁 Vite 5**。

| 套件 | 現在 | 最新 | 為什麼不能升 | 什麼時候再看 |
|---|---|---|---|---|
| `typescript` | 5.9.3 | **7.0.2** | 7 是 Go 重寫的原生版，`exports` 只剩 `unstable/*`，**沒有舊的 JS API**。`vue-tsc` 和 `typescript-eslint`（antfu config 用它）都靠那套 API；`typescript-eslint` 的 peer 寫死 `<6.1.0` | `vue-tsc` 宣布支援 TS 7 之後。中間可以考慮升 **6.0.x**（`typescript-eslint` 允許），但 6 主要是為 7 鋪路的過渡版，收益小 |
| `vitest` | 3.2.7 | 5.0.3 | 5 要 Vite `^6.4 \|\| ^7 \|\| ^8`，VitePress 1.6.4 用 `vite ^5.4`（CLAUDE.md 也寫了） | 跟著 VitePress 2 一起升 |
| `vitepress` | 1.6.4（2025-08） | 2.0.0-alpha.20（`next` tag，Vite 8） | 2.0 從 2025 年到現在還是 **alpha**，最近一版 2026-09-04。1.6.4 已經一年多沒發版 | 2.0 出 RC。到時候 Vite 8、vitest 5、`@vueuse` 版本統一可以一起處理 |

**VitePress 2 值不值得早點跳**：目前不建議。主題是深度客製（`ExpandLayout`、`theme-without-fonts`、`ArticleLayout`、星系頁、sandpack），alpha 期間內部元件路徑常變，`docs/types/shims/` 那套 import 也可能跟著壞。等 RC。

**`markdown-it` 15**：只有一個地方用——叮咚後台的 `console/MarkdownView.vue`（`new MarkdownIt({ html: false, linkify: true })`）。
15 改成 ESM／CJS 雙出口、自帶 `.d.mts` 型別（之後 `@types/markdown-it` 可以拿掉）。我們的用法很單純，升級風險低，但 14 仍在維護（14.3.2 是 09-12 才發的），**不急**。
另外要注意：VitePress 自己內部也用 markdown-it 14（`config.mts` 的 `markdown-it-container` 是掛在 VitePress 那份上），所以升 15 之後倉庫裡會有兩份；只要後台那份是 15、`config.mts` 不去 import 我們的 15 就沒事。

**`@vueuse/core` 重複三份**：我們 15.0.0、tres 系列帶 14.4.0、VitePress 帶 12.8.2。不影響功能（各自用各自的），只是包大一點。不要為了統一去降版，等 VitePress 2 自然收斂。

## 八、安全性（`pnpm audit`）

53 個：24 moderate、29 high。**全部在建置／開發工具鏈裡**（`vite-plugin-svg-icons`、`unplugin-auto-import` 的舊 rollup／vite、`globby`、`stylelint`、`vitest` 的 jsdom），沒有一個會打包進網站——網站是純靜態檔。

## 九、自家訪客系統（取代不蒜子）

### 要做到的

- 文章頁顯示「這頁被看了幾次」、側欄顯示「全站瀏覽數／訪客數」，跟現在不蒜子的三個位置一樣。
- **不用 cookie、不存 IP**。不需要同意橫幅。
- 後端掛了、冷啟動慢，頁面照常顯示，數字是 `--`，不擋任何東西。
- 本機開發（localhost:8086）、叮咚後台與帳號頁不計數。

### 分工

| 誰 | 做什麼 |
|---|---|
| 後端（#0090） | 一個公開端點：記一次瀏覽、同時回傳這頁 PV／全站 PV／全站 UV。不重複訪客用「IP＋UA＋每天換的鹽」雜湊，鹽不落地、隔天丟掉。擋機器人、限流、防亂塞路徑。介面寫進 `api.md` |
| 網頁（我） | 新 feature `features/visitor/`：`api.ts`（Zod 解析）＋一個共用狀態的 hook；`theme/index.ts` 換掉 `reloadBusuanzi`，路由變了就記一次；`ArticleMeta`、`AsideWidget`、`ExpandLayout` 改讀 Vue 的 ref，拿掉所有 `busuanzi_*` id 與輪詢 |

### 網頁這邊的細節

- 路徑由網頁先正規化再送（去掉 query、hash；`/xxx/index.html` 跟 `/xxx/` 視為同一頁），後端仍要自己驗。
- 只在 `location.hostname === 'opshell.me'` 時送；`?api=` 覆寫打本機後端時也送（方便測）。
- 叮咚後台／帳號頁（現在的 `NO_THIRD_PARTY_PATHS`）不送。改成自家後端後它就不算第三方了，但後台與帳號頁本來就不該被計數。
- `apiBase()` 現在在 `features/dindon/apiBase.ts`，訪客功能也要用。依「只從 `index.ts` 匯入」的規則，要把它搬到 `shared/utils/` 或從 `@features/dindon` 匯出——動手時決定。
- 舊的 2024 鐵人賽文章（day25～27）講不蒜子的內容是歷史紀錄，**不改**。

### 要使用者決定的

1. **要不要給起始值**：不蒜子的舊數字拿不回來。你若記得大概的全站 PV／UV，後端可以加一個起始偏移；不記得就從 0 開始。
2. **後台要不要看熱門文章**：後端有資料後，叮咚後台可以加一頁「部落格熱門頁面」。不急，先把計數換好。

### 順序

1. 後端做完端點、寫進 `api.md`（#0090）。
2. 網頁照 `api.md` 接、拿掉不蒜子、`pnpm check`、在 `docs:preview` 實測三個位置。
3. 上線後觀察幾天數字合不合理（機器人有沒有擋掉）。
