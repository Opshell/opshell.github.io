# 2026-10-02：後台的金額全部改用實際帳單；查估算為什麼差

**使用者**：因為有串實際帳單了，而且和估算的金額落差有點大，目前所有的分析和檢視都用實際帳單的金額下去做計算和呈現，然後檢查估算的部分到底哪裡出問題。

## 金額改用實際帳單（`d65fd96`＋修正）

帳單只細到「哪一天、哪個計價項目」，分不出功能與裝置；估算分得出來但金額不準。所以（`billingCalibration.ts`、`useCostCalibration.ts`）：

- **一天、一段期間的總數直接用帳單**：總覽的「Gemini 實付」、逐日成本表裡帳單已經匯出的日子。
- **每個功能、每台裝置、每次請求 = 估算（美元）× 換算係數 k**，k = 近 90 天、帳單已經匯出的日子裡「實付（台幣）÷ 估算（美元）」，
  同時包含匯率與估算漏掉的部分，所以換算後的總和等於帳單。全後台共用一個 k（模組層級，抓一次）。
- 套用的地方：用量報表（Gemini 成本、每次成本 P95、每點額度值、總成本、每台成本、各模型成本）、總覽（逐日成本、各功能成本圖）、
  用量監看（每台成本與總和）。表頭與小字寫「依實際帳單換算（每 US$1 估算＝NT$k）」。帳單抓不到時退回估算、標「（估）」。
- 金額小於 NT$0.1 的寫到四位（每次請求只有幾毫）。原始的美元估算只留在「Google 實際帳單」那一段當對照。
- 功能名稱補齊：帳單截圖、AI 搜尋、小精靈提醒、後台整理 LINE 回報（後端 `usage/record.go` 的七個）。

## 查估算哪裡出問題

- **單價沒錯**：用 BigQuery 帳單（用使用者的 gcloud，唯讀）反推每個計價項目的單價，跟後端 `usage/pricing.go` 一模一樣
  （3.1 flash lite 0.25／1.50、3.5 flash lite 0.30／2.50 美元每百萬 token），匯率 31.70。**落差是 token 數對不上**。
- **App 沒有直接打 Gemini**（Android 沒有 Gemini SDK）；後端七個功能都有記用量。
- **找到的原因**：
  1. 用量報表**刻意排除測試裝置**（`usage/report.go:121`），但 API 控制台試打 AI 是真的收錢；帳單上 9/29、9/30 特別多，正是 #0074 上線試打的兩天。
  2. **被取消的加問記 0 token**（`gemini/attempt.go`），Google 已經讀完輸入很可能照收。
  3. 同一把金鑰的其他用量（本機開發、AI Studio 網頁），後端看不到。
- 用量報表多「估算跟帳單差多少（近 90 天）」（`BillingReconcile.vue`）：實際是估算的幾倍、換算係數、反推的匯率、
  每個計價項目反推的匯率（都差不到 1% 就標「價目表沒問題」）、被取消的加問次數、上面三個原因、逐日對帳（估算換台幣、實付、差額）。
- 各原因各占多少要後端用自己的表逐日對 token：開了溝通板 **#0085**，附上帳單每天、每個模型的 token，
  並請後端把被取消的加問用贏的那次的輸入 token 補進估算、用量報表另列測試裝置、`models` 多逐日、帳單端點多 `usd_rate`。
- 驗證：照真實帳單的數字做假資料（CDP 攔截帳單與用量報表兩支），各頁金額都變成台幣、逐日表用帳單實付、對帳區塊的倍數與原因正確。
